## §1 — Account-state model (one writer per state; every requirement below is derived from this table)

| State | Values | Sole writer | Readers |
|---|---|---|---|
| `P[sym]` — broker position per order symbol | `CONFIRMED(q)` (q may be 0) · `UNKNOWN` | **broker evidence only** (R-M): an automated execution/position read (L-1) or an attended attestation, each with `as_of`; never intent, never an HTTP `accepted`, never the equity GET | admission, ledger, EOD, kill, restart, takeover |
| `W[sym]` — broker working orders per symbol | `CONFIRMED({(order_ref, kind, side, qty, type, price, attached_to)})` · `UNKNOWN` | broker evidence only (same sources); a snapshot older than the frozen freshness window (**one bar period**) degrades to `UNKNOWN` | restart, EOD, kill, takeover, cancel, `CLOSE`, `AMEND` |
| `pending[order_ref]` — listener order table | `sent` → `accepted` → `filled(q)` / `partial(q)` / `cancelled` / `rejected`; `UNKNOWN` after the one-bar outcome timeout or a crash between send and outcome | listener: transport moves `sent`/`accepted`; evidence moves the rest | reservations, R-M, S9 |
| `ledger` — `CapacityLedger` (confirmed micro-equivalents + reservations) and `ExecutionStateStore` (confirmed base per leg) | integers | listener, from `P` and `pending` only (confirmed base moves only on a fill) | sizing, takeover, restart |
| `blocks` — sticky risk-add blocks | set of reasons `{kill, eod, overlay, capacity, restart_unreconciled, unknown_order, feed, protection_gap, arming}` | each reason has one owner that sets and clears it (kill: operator after confirmed flat; eod/overlay: scheduler; restart_unreconciled: a PASS reconciliation; unknown_order: evidence; feed: source health; protection_gap: the recovery `CLOSE` confirming flat; arming: `c1_rail_arm.py`) | admission (any member → refuse every risk-add), the daemon control read |
| `mode` — `c1_dd_state.json` (`settled_close_equity`, `settled_date`, `peak_equity`, `mode_next`) | per session | EOD scheduler after confirmed flatness (R-L); seeded once by TB-B7 (O-3) | sizing, daemon `set_mode` at session open |
| `arm` — `dry_run`, `armed_until` | — | operator through `c1_rail_arm.py` only | admission |
| `adapter[leg]` — checkpoint + execution cursor (open fills as learned from `ExecutionEvent`s, resting intents, indicator/paper state) | per leg | daemon, one atomic write per bar and per consumed event | restart |
| `emit` — daemon emission | `effective_emit = config.emit_enabled ∧ control_read_fresh ∧ ¬control.kill ∧ active_leg_digest_ok` | daemon, from its volume config and the listener control read (R-N) | every emission |
| `operations[operation_id]` — durable protection operations | `prepared`, `sent`, `accepted`, `partial`, `rejected`, `UNKNOWN`, `complete`; kind, scope, target, broker reference and confirmed outcome | listener, persisted before send in `c1_rail_telemetry.py`; broker evidence alone establishes completion | `CLOSE`, `AMEND`, feed-loss redelivery, restart; overlapping scopes serialize |
| `L2` — the recorded route capabilities (a)–(e) of R-B3 | `supported` / `not supported` / `unrecorded` per item, with evidence | operator (documentation or an authorized transmitted validation), before the live packet | daemon registry at boot and listener admission (missing required support refuses new exposure), `CLOSE`/`AMEND` |

**Action classes.** *Risk-adding:* `entry`, `add`, a **loosening** `amend`, a **cancel of a protective order outside `CLOSE`/`AMEND`** while its position is not `CONFIRMED(0)`, a cancel whose target kind is unknown. *Risk-reducing:* `exit`, `flat`, `closeposition`, a cancel of a resting `entry`/`add`, a **tightening** `amend`, a cancel of a protective order whose position is `CONFIRMED(0)` (orphan removal — a surviving stop could open the other side). The listener classifies every action from `pending[order_ref].kind`, `W` and the leg's confirmed allocation, never from the daemon's label.

**Execution primitives (defined once; every sequence that touches protection uses them).**
- **`CLOSE(scope)`** — scope = one fill, one leg or one symbol. Requires verified `L2(d)` and `L2(e)`: a broker-native scoped reduction that atomically adjusts the scope's attached protection to the remaining quantity on every partial fill and removes it on final flatness; the close and protection cannot over-execute into a reverse position. The listener confirms completion from fresh `P` and `W`, never from HTTP acceptance. For `CLOSE(leg)` / `CLOSE(symbol)` with unknown quantity, use the verified quantity-less position-close primitive on the exclusively owned symbol (D-B9), never a guessed quantity or a fabricated fill scope. **No sequential or concurrent cancel-plus-market-close fallback is built:** putting two requests in one software step does not make broker execution atomic. Persist the operation identity, scope and outcome before send; serialize overlapping `CLOSE`/`AMEND` operations. Set the account-wide `unknown_order` block while a close is unresolved; clear it only after evidence resolves every operation owning that reason. Rejection retains the existing protection and the risk-add block; an unknown outcome is reconciled before resubmission, never blindly retried. Recovery resumes the same durable operation after restart and alerts on unresolved exposure. If the route cannot meet these properties, new exposure is blocked at admission and the live packet is `BLOCKED — capability-problem`; a capability failure discovered with exposure already present retains protection, blocks risk-adds and requires attended recovery rather than inventing unsupported commands.
- **`AMEND(order_ref, level | qty)`** — protective-order change (recomputed stop, trailing update, bracket quantity). Requires verified `L2(c)`: broker-native atomic modify, with the old protection remaining effective until the new protection takes effect and with no interval where two independent stops can over-execute. **Cancel/replace is not a supported realization.** Persist the operation identity and target before send; serialize against overlapping `CLOSE`/`AMEND`. Rejection leaves the old protection working; an unknown outcome sets the account-wide `unknown_order` block and reconciles `P` and `W` before another modification or resubmission. If reconciliation proves the position unprotected, set the account-wide `protection_gap` block and initiate the verified `CLOSE(scope)` recovery; retain the block and alert until broker evidence confirms flatness and removal of the scope's orders. Recovery is not a substitute for atomic modify capability. A tightening `AMEND` is risk-reducing; a loosening one is risk-adding.

**Invariants.** **I1** — an `UNKNOWN` in any state an action reads refuses every risk-adding action. Risk-reducing requests remain admissible; broker dispatch still obeys the operation-identity, scope and reconciliation rules of `CLOSE`/`AMEND`, so admission never means guessing a target or duplicating an unresolved send. **I2** — only broker evidence moves `P`, `W`, `pending` past `accepted`, `ledger.confirmed` and any adapter position state; intent moves `pending` to `sent` and takes a reservation, nothing else. **I3** — every block is sticky across restarts and cleared only by its owner's confirmed completion. **I4** — exactly one authority computes a broker quantity for a risk-adding order: the listener's sizing host (R-Q); `OrderIntent.qty` on `entry`/`add` is the **adapter-normal** quantity (a positive int, as the delivered constructor requires) and reaches the listener as `qty_normal`; a broker quantity travels only on `exit`/`flat`. **I5** — a checkpoint and its execution cursor are one atomic write; an event id is applied at most once. **I6** — the listener's `blocks` make any daemon emission inert; daemon quiescence is a second layer, never the safety property. **I7 (rev 5.1)** — every admitted protection transition preserves effective protection for the remaining position continuously, including between broker events, and cannot leave an executable orphan that opens reverse exposure. `AMEND` changes protection atomically; `CLOSE` reduces position and protection together. A detected breach is an incident requiring the durable recovery above, not a permitted transient state or a promise that recovery always succeeds. **I8 (rev 5)** — the rail executes only the semantics the emulator qualified: resting stop entries filled intrabar, brackets attached per entry fill, per-bar bracket re-issue applied from the next bar, market orders at the signal. For strategy-generated orders the one accepted deviation class is **latency** (an order reaches the broker seconds after the bar close instead of at `THIS_CLOSE`/`NEXT_OPEN`), measured in Phase 8 execution parity with a frozen tolerance (`OWED-BY: TB-F1`). A semantic substitute — a daemon-held stop, a closed-bar exit, a synthesized trail — is a different strategy and is never built. The separately ratified S6 emergency feed-loss flat is an operational risk-reduction exception, not a claim of replay parity; its exact authorization is §5 (3).

## §2 — Event sequences (component · state read/written · fail-closed outcome; TB-I3 drives each sequence end to end through the simulated broker and asserts every transition — test `test_seq_s<n>_*`)

**S1 — market entry / add** (Aegis, Striker, Vanguard entry and add, ORB add). (1) adapter `on_bar` → `OrderIntent(kind, side, qty=<adapter-normal quantity>)` (positive int; adapter units — R-P) [daemon; adapter state only]. (2) barrier collects the bar's completion events and releases in the RC-5 order [`barrier.py`]. (3) `effective_emit` [daemon; control read older than one bar or unreadable → no emission, `control_read_failed`]. (4) B1 payload `{leg_id, signal_type, bar_time, close, stop_dist_pts, side, qty_normal, stop_loss?, take_profit?}` — **no `qty`** [`b1_payload.py` maps `OrderIntent.qty` → `qty_normal`; a `sell` to open for an Equity-Index leg is refused at build]. (5) listener admission in this order: test identity → `blocks` (any member → `policy_block`) → arming expiry → side vs `allowed_entry_side` and the hedging bar → dedupe (TB-I4) → lifecycle (`watch_tiers_zero`) → `mode` (`settled_date` ≠ prior venue session → halt) → quantity law (R-Q, exact rational, from `qty_normal`) → capacity (refuse-never-clip; Aegis may enter S10) [listener; writes `pending=sent` + reservation **before** send]. (6) send with the attached bracket fields (`dry_run` → never) → `SendResult` [`pending=accepted`]. (7) broker evidence: fill / partial / reject; the fill's attached protective orders appear in `W` with `attached_to` = the entry order [`pending`, `P`, `W`, `ledger.confirmed`; reservation released on reject, cancel or one-bar staleness]. (8) `ExecutionEvent` served at `/executions?since=<cursor>` → adapter `on_execution` (the adapter learns the **executed** quantity here and sizes its exits from it) → checkpoint + cursor [daemon, atomic]. **Cuts:** no evidence within one bar → `pending=UNKNOWN`, reservation held, `blocks += unknown_order` for that leg until evidence.

**S2 — ORB stop entry (one branch).** Step 4 carries `stop_price`; step 5 admits the risk-add at the stop's quantity and holds the reservation while it rests; the listener sends `order_type=stop` with the bracket fields (`L2(a)` and `L2(b)` must be `supported`); `W[MNQ]` gains the order on evidence; it fills intrabar when crossed, exactly as the emulator fills it; a resting entry older than one bar is cancelled (RC-9) unless re-issued; a fill continues at S1 (7). The buy-only ORB port (D-B7) emits one resting entry per day, so two OCA siblings are never live; daemon-side OCA is not built (test: never two resting entries for one leg). **No fallback:** if `L2(a)` is not `supported`, the registry refuses to run the ORB leg and the live packet is `BLOCKED — capability-problem` (a market entry after the crossing bar closes is a different strategy from the qualified one — I8; D-B4 allows no substitute book).

**S3 — brackets and per-bar re-issue (one branch).** Every entry/add carries its bracket (`stop_loss`, `take_profit`; trailing as the port expresses it), so `W` gains the protective orders **with the fill** (`L2(b)`). The ports re-issue their exit levels every bar as Pine re-calls `strategy.exit`; live that is `AMEND` per closed bar, applied at the broker seconds after the close, which the emulator models as the new level taking effect from the next bar (I8 latency class). A tightening `AMEND` is risk-reducing (admitted under blocks, timeouts, late arrival); a loosening one is risk-adding (refused under any block). Atomic-modify rejection, unknown outcome and recovery follow `AMEND` (§1); sequential cancel/replace is never used. **No fallback:** if `L2(b)` or `L2(c)` is not `supported`, every bracketed leg is refused at the registry and the live packet is `BLOCKED — capability-problem`; a daemon-evaluated closed-bar exit is not the qualified strategy (the emulator evaluates protection along the intrabar path).

**S4 — cancel.** `cancel(order_ref)` from the adapter (ORB adds at a mode change through `set_mode`; stale resting entries) → the listener reads `pending[order_ref].kind` and `W`: resting entry/add → risk-reducing → send, require the broker cancel acknowledgement, release the reservation; protective → refused outside `CLOSE`/`AMEND` unless its position is `CONFIRMED(0)` (orphan removal, risk-reducing); unknown ref → refused + alert.

**S5 — scoped exit / flat.** `exit` carries `qty` = the adapter's confirmed open quantity in scope (learned from fills, never from intent); the listener clamps `qty` **down** to the leg's confirmed allocation (never up; `exit_qty_clamped`) and runs **`CLOSE(fill scope)`**, which uses the verified `L2(d)`/`L2(e)` atomic reduction: protection remains effective for any unclosed remainder after each partial fill and is removed only when that scope is flat. Merely requesting a whole-fill close does not prove these properties; they require route evidence and partial-fill tests. `flat` = `CLOSE(leg)`. Both are risk-reducing (admitted under every block, timeout and late arrival). Fill → `P`, `W`, `ledger`, `ExecutionEvent`.

**S6 — barrier timeout, late arrival, unhealthy source.** One source stale (S2b staleness formula, `2 × bar_period + 30 s`) or one leg silent past the barrier timeout (one bar period + 30 s): the barrier releases the bar with only its risk-reducing actions; every risk-add of every leg is refused for that bar (`barrier_timeout`); a late risk-reducing arrival for a closed bar is admitted, a late risk-add refused; the leg on the stale source emits nothing until its bar arrives, **with one exception — the feed-loss flat:** a leg whose source stays unhealthy past the staleness window and whose symbol is **not `CONFIRMED(0)`** (confirmed non-zero **or `UNKNOWN`**) receives one daemon `flat` intent (`feed_loss_flat`) per feed-loss episode; the listener durably owns the resulting `CLOSE(leg)` through completion, including when the daemon stops or the position quantity is unknown. This timer is independent of new bar arrivals; transport redelivery uses the same operation identity and cannot initiate a second close. Rationale: the strategy's exit logic cannot run without bars, and a resting bracket alone is not the qualified exit set; the flat is live-only, risk-reducing, and the replay has no counterpart (recorded as such). **This is the exact signal §5 (3) authorizes; until the addendum is ratified the S2b Fail-closed row governs and TB-I3 must not implement it.**

**S7 — EOD.** At the buffer (16:30 ET regular, 12:44 ET early close; an overlay date blocks the whole session): (1) `blocks += eod`; (2) cancel every resting `entry`/`add` across legs, broker acknowledgements required; (3) **`CLOSE(symbol)`** for every symbol with `P ≠ CONFIRMED(0)`, `UNKNOWN` included (the primitive handles the symbol's protective orders through verified `L2(d)`/`L2(e)` atomic reduction — never a bare `closeposition` beside standing standalone stops); (4) confirm `P = CONFIRMED(0)` on every owned symbol; (5) confirm `W = ∅` on every symbol, cancelling any orphan (acknowledgements); (6) settle `mode` (R-L), reset per-day state; `eod` clears at the next session open. Any failed, partial, rejected, unknown or timed-out step leaves `eod` set, retains per-day state, reports the exposure and alerts. Steps run only in this order.

**S8 — kill switch (operator).** `c1_rail_arm.py --kill`: (1) `blocks += kill` on the listener volume **first** — from this instant every risk-adding admission is refused whatever the daemon does (I6); (2) the control endpoint (R-N) serves `kill=true`, so a running daemon's next control read drops `effective_emit` and it stops emitting risk-adds (its risk-reducing actions are still admitted); (3)–(5) = S7 (2)–(5); (6) `--disarm`; (7) **daemon-app acknowledgement:** the operator sets `emit_enabled=false` in the daemon's `/data` config on the separate Fly app (`fly ssh console` + the atomic config write `m1_stage1_control.py` already uses) and runs `--kill-status`, which records `daemon_control: acknowledged | not_reached` from the daemon's `GET /` heartbeat. **Completion** = `P = CONFIRMED(0)` and `W = ∅` on every owned symbol and disarmed; the acknowledgement is reported beside it and its absence is an open alert, not a reason to withhold "flat" (step 1 already makes any emission inert). Callable with the daemon down (steps 1 and 3–6 need only the listener); a failed/partial/unknown close leaves `kill` set and reports the remaining exposure; `kill` clears only by the operator after confirmed flatness. Recorded as an `arming_deviation`-class ledger event (`kill_switch`); never automatic on a signal; the O-1 beta-death event routes here as an operator action, not a multiplier.

**S9 — crash and restart (cut at every S1 step and every protection-operation send/outcome boundary).** *Listener:* restore `operations` first; resume/reconcile each unresolved `CLOSE`/`AMEND` using its original identity before any overlapping dispatch; never infer that a missing acknowledgement means no execution. Then rebuild `ledger` from `ExecutionStateStore` + `pending`; `blocks += restart_unreconciled`; require `P` **and** `W` `CONFIRMED` for every owned symbol through R-M (L-1); reconcile `pending` against `W`: an order in `W` absent from `pending` (orphan), or in `pending` as `sent`/`accepted` but absent from `W`, halts that leg with `restart_orphan_order` and an alert; **an orphan of unknown kind is never auto-cancelled** (it may be protection); a position in `P` with no protective order in `W` is a `protection_gap` → recovery `CLOSE(symbol)`; the block clears only on a PASS reconciliation. *Daemon:* restore each adapter from its checkpoint, resume the cursor, consume outstanding events, then compare the adapter's open fills and resting intents with `P` and `W` for its symbol; mismatch → that leg halts; no checkpoint → cold start holds emission for TB-W1's counts. A crash between S1 (6) and (7) leaves `pending=UNKNOWN` with its reservation held until evidence; between (7) and (8) the event is re-served from the cursor and applied once (I5).

**S10 — capacity takeover (Aegis, D-B8).** Under `blocks = ∅`: cancel displaced resting entries/adds (acknowledgements) → **`CLOSE(symbol)`** per displaced symbol → `P = CONFIRMED(0)` and the symbol's `W` empty on each → reconcile → admit Aegis; any unacknowledged cancel or partial/rejected/unknown/timed-out close refuses Aegis and leaves the displaced legs as they are (never half-closed). Under O-5/O-6 the protected Striker ceiling is 77 micro-equivalents, so the protected path is reachable and tested.
