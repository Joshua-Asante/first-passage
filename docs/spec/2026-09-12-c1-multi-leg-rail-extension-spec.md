## §1 — Account-state model (one writer per state; every requirement below is derived from this table)

| State | Values | Sole writer | Readers |
|---|---|---|---|
| `P[sym]` — broker position per order symbol | `CONFIRMED(q)` (q may be 0) · `UNKNOWN` | **broker evidence only** (R-M): an automated execution/position read (L-1) or an attended attestation, each with `as_of`; never intent, never an HTTP `accepted`, never the equity GET | admission, ledger, EOD, kill, restart, takeover |
| `W[sym]` — broker working orders per symbol | `CONFIRMED({(order_ref, kind, side, qty, type, price)})` · `UNKNOWN` | broker evidence only (same sources); a snapshot older than the frozen freshness window (**one bar period**) degrades to `UNKNOWN` | restart, EOD, kill, takeover, cancel |
| `pending[order_ref]` — listener order table | `sent` → `accepted` → `filled(q)` / `partial(q)` / `cancelled` / `rejected`; `UNKNOWN` after the one-bar outcome timeout or a crash between send and outcome | listener: transport moves `sent`/`accepted`; evidence moves the rest | reservations, R-M, S9 |
| `ledger` — `CapacityLedger` (confirmed micro-equivalents + reservations) and `ExecutionStateStore` (confirmed base per leg) | integers | listener, from `P` and `pending` only (confirmed base moves only on a fill) | sizing, takeover, restart |
| `blocks` — sticky risk-add blocks | set of reasons `{kill, eod, overlay, capacity, restart_unreconciled, unknown_order, feed, arming}` | each reason has one owner that sets and clears it (kill: operator after confirmed flat; eod/overlay: scheduler; restart_unreconciled: a PASS reconciliation; unknown_order: evidence; feed: source health; arming: `c1_rail_arm.py`) | admission (any member → refuse every risk-add), the daemon control read |
| `mode` — `c1_dd_state.json` (`settled_close_equity`, `settled_date`, `peak_equity`, `mode_next`) | per session | EOD scheduler after confirmed flatness (R-L); seeded once by TB-B7 (O-3) | sizing, daemon `set_mode` at session open |
| `arm` — `dry_run`, `armed_until` | — | operator through `c1_rail_arm.py` only | admission |
| `adapter[leg]` — checkpoint + execution cursor (open fills as learned from `ExecutionEvent`s, resting intents, indicator/paper state) | per leg | daemon, one atomic write per bar and per consumed event | restart |
| `emit` — daemon emission | `effective_emit = config.emit_enabled ∧ control_read_fresh ∧ ¬control.kill ∧ active_leg_digest_ok` | daemon, from its volume config and the listener control read (R-N) | every emission |

**Action classes.** *Risk-adding:* `entry`, `add`, a **loosening** `amend`, a **cancel of a protective order**, a cancel whose target kind is unknown. *Risk-reducing:* `exit`, `flat`, `closeposition`, a cancel of a resting `entry`/`add`, a **tightening** `amend`. The listener classifies every action from `pending[order_ref].kind` and the leg's confirmed allocation, never from the daemon's label.

**Invariants.** **I1** — an `UNKNOWN` in any state an action reads refuses every risk-adding action and never delays a risk-reducing one. **I2** — only broker evidence moves `P`, `W`, `pending` past `accepted`, `ledger.confirmed` and any adapter position state; intent moves `pending` to `sent` and takes a reservation, nothing else. **I3** — every block is sticky across restarts and cleared only by its owner's confirmed completion. **I4** — exactly one authority computes a broker quantity for a risk-adding order: the listener's sizing host (R-Q); the daemon carries `qty_normal` (adapter units) on `entry`/`add` and a broker quantity only on `exit`/`flat`. **I5** — a checkpoint and its execution cursor are one atomic write; an event id is applied at most once. **I6** — the listener's `blocks` make any daemon emission inert; daemon quiescence is a second layer, never the safety property. **I7** — a position is never stripped of its protective orders before it is `CONFIRMED(0)`.

## §2 — Event sequences (component · state read/written · fail-closed outcome; TB-I3 drives each sequence end to end through the simulated broker and asserts every transition — test `test_seq_s<n>_*`)

**S1 — market entry / add** (Aegis, Striker, Vanguard entry and add, ORB add). (1) adapter `on_bar` → `OrderIntent(kind, side, qty=None)` plus `qty_normal` for `adapter_quantity` legs [daemon; adapter state only]. (2) barrier collects the bar's completion events and releases in the RC-5 order [`barrier.py`]. (3) `effective_emit` [daemon; control read older than one bar or unreadable → no emission, `control_read_failed`]. (4) B1 payload `{leg_id, signal_type, bar_time, close, stop_dist_pts, side, qty_normal?}` — **no `qty`** [`b1_payload.py`; a `sell` to open for an Equity-Index leg is refused at build]. (5) listener admission in this order: test identity → `blocks` (any member → `policy_block`) → arming expiry → side vs `allowed_entry_side` and the hedging bar → dedupe (TB-I4) → lifecycle (`watch_tiers_zero`) → `mode` (`settled_date` ≠ prior venue session → halt) → quantity law (R-Q, exact rational) → capacity (refuse-never-clip; Aegis may enter S10) [listener; writes `pending=sent` + reservation **before** send]. (6) send (`dry_run` → never) → `SendResult` [`pending=accepted`]. (7) broker evidence: fill / partial / reject [`pending`, `P`, `ledger.confirmed`; reservation released on reject, cancel or one-bar staleness]. (8) `ExecutionEvent` served at `/executions?since=<cursor>` → adapter `on_execution` → checkpoint + cursor [daemon, atomic]. **Cuts:** no evidence within one bar → `pending=UNKNOWN`, reservation held, `blocks += unknown_order` for that leg until evidence.

**S2 — ORB stop entry.** *L-2 stop supported:* step 4 carries `stop_price`; step 5 admits the risk-add at the stop's quantity and holds the reservation while it rests; the listener sends `order_type=stop`; `W[MNQ]` gains the order on evidence; a resting entry older than one bar is cancelled (RC-9) unless re-issued; a fill continues at S1 (7). *L-2 not supported:* the daemon holds the level and emits a market `entry` on the first closed bar whose high crosses it (deviation recorded; stress cell); nothing rests at the broker; **under feed loss on MNQ a daemon-held level cannot trigger** — S6 governs. The buy-only ORB port (D-B7) emits one resting entry per day, so two OCA siblings are never live; daemon-side OCA is not built (test: never two resting entries for one leg).

**S3 — brackets and trailing amend.** *L-2 brackets supported:* `stop_loss` / `take_profit` ride the entry send, so `W` gains the protective orders with the fill; the trailing stop is an `amend` (cancel/replace) per bar — tightening is risk-reducing (admitted under blocks, timeouts, late arrival), loosening is risk-adding (refused under any block). *Not supported:* protective exits are daemon-evaluated on closed bars exactly as the emulator does and emitted as `exit`; feed loss → the S6 feed-loss flat. One test per branch.

**S4 — cancel.** `cancel(order_ref)` from the adapter (ORB adds at a mode change through `set_mode`; stale resting entries) → the listener reads `pending[order_ref].kind`: entry/add → risk-reducing → send, require the broker cancel ack, release the reservation; protective → risk-adding → refused unless the position it protects is `CONFIRMED(0)`; unknown ref → refused + alert.

**S5 — scoped exit / flat.** `exit` carries `qty` = the adapter's confirmed open quantity in scope (learned from fills, never from intent); the listener clamps `qty` **down** to the leg's confirmed allocation (never up; `exit_qty_clamped`); `flat` = every confirmed fill of the leg; both are risk-reducing (admitted under every block, timeout and late arrival); the quantity-less `closeposition` is reserved for S7/S8/S10. Fill → `P`, `ledger`, `ExecutionEvent`.

**S6 — barrier timeout, late arrival, unhealthy source.** One source stale (S2b staleness formula) or one leg silent past the barrier timeout (one bar period + 30 s): the barrier releases the bar with only its risk-reducing actions; every risk-add of every leg is refused for that bar (`barrier_timeout`); a late risk-reducing arrival for a closed bar is admitted, a late risk-add refused; the leg on the stale source emits nothing until its bar arrives. **Feed-loss flat — only where protection is daemon-held (the "not supported" branches of S2/S3):** a symbol with `P ≠ CONFIRMED(0)` whose source stays unhealthy past the staleness window receives a `flat` from the daemon (`feed_loss_flat`); under broker-resting protection no flat is emitted, the resting stop stands and trailing amends pause. **This paragraph is the S2b exception that §5's addendum authorizes; until it is ratified the S2b Fail-closed row governs and TB-I3 must not implement it.**

**S7 — EOD.** At the buffer (16:30 ET regular, 12:44 ET early close; an overlay date blocks the whole session): (1) `blocks += eod`; (2) cancel every resting `entry`/`add` across legs, broker acks required; (3) `closeposition` for every symbol with `P ≠ CONFIRMED(0)`, `UNKNOWN` included; (4) confirm `P = CONFIRMED(0)` on every owned symbol; (5) **only then** cancel the remaining protective orders (acks required — I7); (6) confirm `W = ∅` on every symbol; (7) settle `mode` (R-L), reset per-day state; `eod` clears at the next session open. Any failed, partial, rejected, unknown or timed-out step leaves `eod` set, retains per-day state, reports the exposure and alerts. Steps run only in this order.

**S8 — kill switch (operator).** `c1_rail_arm.py --kill`: (1) `blocks += kill` on the listener volume **first** — from this instant every risk-adding admission is refused whatever the daemon does (I6); (2) the control endpoint (R-N) serves `kill=true`, so a running daemon's next control read drops `effective_emit` and it stops emitting risk-adds (its risk-reducing actions are still admitted); (3)–(6) = S7 (2)–(6); (7) `--disarm`; (8) **daemon-app acknowledgement:** the operator sets `emit_enabled=false` in the daemon's `/data` config on the separate Fly app (`fly ssh console` + the atomic config write `m1_stage1_control.py` already uses) and runs `--kill-status`, which records `daemon_control: acknowledged | not_reached` from the daemon's `GET /` heartbeat. **Completion** = `P = CONFIRMED(0)` and `W = ∅` on every owned symbol and disarmed; the acknowledgement is reported beside it and its absence is an open alert, not a reason to withhold "flat" (step 1 already makes any emission inert). Callable with the daemon down (steps 1 and 3–7 need only the listener); a failed/partial/unknown close leaves `kill` set and reports the remaining exposure; `kill` clears only by the operator after confirmed flatness. Recorded as an `arming_deviation`-class ledger event (`kill_switch`); never automatic on a signal; the O-1 beta-death event routes here as an operator action, not a multiplier.

**S9 — crash and restart (cut at every S1 step).** *Listener:* rebuild `ledger` from `ExecutionStateStore` + `pending`; `blocks += restart_unreconciled`; require `P` **and** `W` `CONFIRMED` for every owned symbol through R-M (L-1); reconcile `pending` against `W`: an order in `W` absent from `pending` (orphan), or in `pending` as `sent`/`accepted` but absent from `W`, halts that leg with `restart_orphan_order` and an alert; **an orphan of unknown kind is never auto-cancelled** (it may be protection); the block clears only on a PASS reconciliation. *Daemon:* restore each adapter from its checkpoint, resume the cursor, consume outstanding events, then compare the adapter's open fills and resting intents with `P` and `W` for its symbol; mismatch → that leg halts; no checkpoint → cold start holds emission for TB-W1's counts. A crash between S1 (6) and (7) leaves `pending=UNKNOWN` with its reservation held until evidence; between (7) and (8) the event is re-served from the cursor and applied once (I5).

**S10 — capacity takeover (Aegis, D-B8).** Under `blocks = ∅`: cancel displaced resting entries/adds (acks) → `closeposition` per displaced symbol → `P = CONFIRMED(0)` on each → cancel their protective orders (acks; I7) → reconcile → admit Aegis; any unacknowledged cancel or partial/rejected/unknown/timed-out close refuses Aegis and leaves the displaced legs as they are (never half-closed). Under O-5/O-6 the protected Striker ceiling is 77 micro-equivalents, so the protected path is reachable and tested.

**Consistency matrix** (event × state):

| | `P = UNKNOWN` | `W = UNKNOWN` | `pending = UNKNOWN` | source unhealthy | `blocks ≠ ∅` |
|---|---|---|---|---|---|
| risk-add admission [listener] | refuse | refuse | refuse (that leg) | refuse (every leg, that bar) | refuse |
| exit / flat / tightening amend [listener] | send | send | send | send | send |
| EOD [scheduler] | close the symbol | proceed; `W = ∅` required before reset | proceed; resolved or cancelled before reset | proceed (S6 may already have flattened) | proceed |
| kill [operator] | close the symbol | proceed; `W = ∅` required for completion | same | proceed | proceed |
| restart [listener / daemon] | block until confirmed | block until confirmed | hold the reservation until evidence | hold that leg's emission | keep every block |
| daily reset [scheduler] | never | never | never | after confirmed flat | after the owner clears |

## §5 — Proposed S2b build ADR addendum (verbatim text for the operator to ratify; lands on the S2b ADR as a dated addendum, not here)

> **Addendum 2026-09-DD — Tradeify portfolio: B1 contract extension and per-source risk-reduction exception (TB-S3 rev 4).** *Amends in place (Rule 14 class 2)* the §2 **Listener** row and the §2 **Fail-closed** row for the four-leg fixed book only. **(1) B1 fields and signal types.** The B1 payload may carry the optional fields `side`, `qty_normal`, `qty`, `stop_price`, `stop_loss`, `take_profit`, `order_ref` and the signal types `cancel` and `amend` exactly as `docs/spec/2026-09-12-c1-multi-leg-rail-extension-spec.md` R-B1/R-B3 define them; the five-field payload remains valid; §4 limb 3 is not triggered by these fields. **(2) Per-source fail-closed.** With four bar sources, "unhealthy/stale/missing feed" is evaluated **per source**. An unhealthy source (i) blocks every risk-adding signal (`entry`, `add`, loosening `amend`, protective `cancel`) of **every** leg for the affected bar and (ii) blocks every signal of the leg on that source until its bar arrives; risk-reducing signals (`exit`, `flat`, `cancel` of a resting entry/add, tightening `amend`) from legs on healthy sources are emitted. **(3) Feed-loss flat.** Only where the recorded L-2 capability leaves a leg's protection daemon-held, a symbol with a confirmed non-zero position whose source stays unhealthy past the staleness window receives a `flat`; where protection rests at the broker no signal is emitted. §4 limb 2 is re-scoped to "emits a **risk-adding** signal while its source is unhealthy, or emits any signal for the leg on an unhealthy source before its bar arrives". Everything else in §2 stands; the single-strategy daemon's behaviour is unchanged until the four-leg registry is deployed.
