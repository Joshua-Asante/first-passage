## §1 — Account-state model (one writer per state; every requirement below is derived from this table)

| State | Values | Sole writer | Readers |
|---|---|---|---|
| `P[sym]` — broker position per order symbol | `CONFIRMED(q)` (q may be 0) · `UNKNOWN` | **broker evidence only** (R-M): an automated execution/position read (L-1) or an attended attestation, each with `as_of`; never intent, never an HTTP `accepted`, never the equity GET | admission, ledger, EOD, kill, restart, takeover |
| `W[sym]` — broker working orders per symbol | `CONFIRMED({(order_ref, kind, side, qty, type, price, attached_to)})` · `UNKNOWN` | broker evidence only (same sources); a snapshot older than the frozen freshness window (**one bar period**) degrades to `UNKNOWN` | restart, EOD, kill, takeover, cancel, `CLOSE`, `AMEND`, `ATTACH` |

| `adapter[leg]` — checkpoint + execution cursor (open fills as learned from `ExecutionEvent`s, the bracket the port currently defines per fill, resting intents, indicator/paper state) | per leg | daemon, one atomic write per bar and per consumed event | restart |

| `expected_protection[fill]` — the protection the strategy has defined for an open fill | per fill: the **intended** bracket (from the admitted intent or attach, recorded `prepared` **before send**) and, per component, `working` / `not_working` as broker evidence confirms it **at the intended parameters** (a component present at other parameters is missing); empty only for a lot the port has not yet protected | listener: intent writes the intended set (never a confirmation); postdating evidence marks components working or absent and removes them on fill/cancel confirmation | `protection_gap` detection (S1 (7), S9, `AMEND`), `CLOSE` |
| `last_control_read` — daemon liveness | timestamp | listener, persisted on every control read in the same store as `operations` (atomic write) and **restored before any daemon-loss evaluation**; absent or unparseable at boot ⇒ treated as **expired** | S6 daemon-loss timer |
| `L2` — the recorded route capabilities (a)–(g) of R-B3 | `supported` / `not supported` / `unrecorded` per item, with evidence | operator (documentation or an authorized transmitted validation), before the live packet | daemon registry at boot and listener admission (missing required support refuses new exposure), `CLOSE`/`AMEND`/`ATTACH` |

**Action classes.** *Risk-adding:* `entry`, `add`, a **loosening** `amend` (a stop moved away from the market; for a trail, a larger activation distance or a larger offset), a **cancel of a protective order outside `CLOSE`/`AMEND`** while its position is not `CONFIRMED(0)`, a cancel whose target kind is unknown. *Risk-reducing:* `exit`, `flat`, `closeposition`, a cancel of a resting `entry`/`add`, a **tightening** `amend`, an `attach` of the port's first protection to a bare lot, a cancel of a protective order whose position is `CONFIRMED(0)` (orphan removal — a surviving stop could open the other side). The listener classifies every action from `pending[order_ref].kind`, **fresh** `W` and the leg's confirmed allocation, never from the daemon's label; tightening versus loosening is decided against the working order's current level in `W`, so an `amend` whose target is not in a fresh `W` cannot be classified and is refused (S3).

**Evidence currency (applies to every primitive).** An operation's completion, and any no-op determination, uses only `P`/`W` evidence whose `as_of` is **strictly after** the operation's `prepared_at` — an equal instant proves no read-after-prepare order; the one-bar freshness window is an upper bound on age, never a substitute for postdating. A 16:25 snapshot cannot complete a 16:30 close, and neither can a read stamped 16:30. Gap detection runs on order-level reads only: a position-only read never manufactures a gap. A **position-only read** (no working-order list, no order status) never completes or settles an operation, exactly as it never resolves an order (`pending` row): absent order-level data is not flatness.

**Execution primitives (defined once; every sequence that touches protection uses them).**
- **`CLOSE(scope)`** — scope = one fill, one leg or one symbol. Requires verified `L2(d)` and `L2(e)`: a broker-native scoped reduction that atomically adjusts the scope's attached protection to the remaining quantity on every partial fill and removes it on final flatness; the close and protection cannot over-execute into a reverse position. The listener confirms completion from `P` and `W` evidence that postdates `prepared_at`, never from HTTP acceptance. For `CLOSE(leg)` / `CLOSE(symbol)` with unknown quantity, use the verified quantity-less position-close primitive on the exclusively owned symbol (D-B9), never a guessed quantity or a fabricated fill scope. **No sequential or concurrent cancel-plus-market-close fallback is built:** putting two requests in one software step does not make broker execution atomic. Persist the operation identity, scope, `prepared_at` and outcome before send. **Overlapping operations on one symbol queue in turn:** one close in flight per symbol; a later, broader close (EOD, kill, recovery) on a symbol with an unresolved narrower close is `queued` and dispatched when that one resolves — never dropped; a request on a scope that already has a prepared, queued, rejected or unresolved operation returns that operation. Set the account-wide `unknown_order` block while a close is unresolved; clear it only after evidence resolves every operation owning that reason. Rejection retains the existing protection and sets the durable **`close_rejected`** block for a scope that still has exposure (owner: the listener's retry — after reconciliation on postdating evidence the same operation is resubmitted at most once per bar, alerting each time; cleared only when **no rejected or refused close remains** — every such scope confirmed flat on postdating evidence — or by a recorded operator clear after attended recovery); an unknown outcome is reconciled from postdating evidence before resubmission, never blindly retried; a **partial** outcome (residual exposure on postdating evidence) resumes through the **same** operation, for the remainder only, after that reconciliation — never a new operation. Recovery resumes the same durable operation after restart and alerts on unresolved exposure. If the route cannot meet these properties, new exposure is blocked at admission and the live packet is `BLOCKED — capability-problem`; a capability failure discovered with exposure already present retains protection, blocks risk-adds and requires attended recovery rather than inventing unsupported commands. A `CLOSE` whose scope is already `CONFIRMED(0)` with no attached orders **on evidence that postdates `prepared_at`** completes as a no-op without a send (idempotent by scope), so an adapter's own `flat` arriving after a scheduler, kill or recovery `CLOSE` never produces a second order.
- **`AMEND(order_ref, level | qty)`** — change of protection the port has already defined (recomputed stop, trailing parameters, bracket quantity). Requires verified `L2(c)`: broker-native atomic modify, with the old protection remaining effective until the new protection takes effect and with no interval where two independent stops can over-execute. **Requires the target in a fresh `W`** (`as_of` within one bar and after the last operation on that fill): with `W = UNKNOWN` the amend is refused (`amend_deferred`), `W` is reconciled through R-M, and the port's next per-bar re-issue supplies the level again — nothing is guessed, and a loosening change can never pass as tightening. **Cancel/replace is not a supported realization.** The listener diffs the re-issued bracket against `expected_protection[fill]` and modifies **only the components whose level or parameters changed**; unchanged components — in particular an active native trail — are never re-sent, so the broker's accumulated trailing anchor is never disturbed (the emulator likewise keeps `trail_active` / `trail_extreme` when it replaces a bracket). Persist the operation identity and target before send; an unresolved operation on the same lot defers a new amend (`amend_deferred`) until it resolves. Rejection leaves the old protection working; an unknown outcome sets the account-wide `unknown_order` block and reconciles `P` and `W` (postdating evidence) before another modification or resubmission. If reconciliation proves an expected protective order absent, set the account-wide `protection_gap` block and initiate the verified `CLOSE(scope)` recovery; retain the block and alert until broker evidence confirms flatness and removal of the scope's orders. Recovery is not a substitute for atomic modify capability. A tightening `AMEND` is risk-reducing; a loosening one is risk-adding.
- **`ATTACH(fill scope, bracket)`** — the port's **first** protection for a lot that entered bare (the emulator's "attach an order to a lot that never had one": Striker issues its exit a bar after the entry). Requires verified `L2(f)`: the route can attach stop/limit/trailing protection to an existing open fill **linked to the position** so that `L2(d)`/`L2(e)` semantics hold afterwards — a standalone stop that would survive a close is not an attach. Persisted like `AMEND`; a **rejection is a `protection_gap` immediately** — the exposure is known unprotected — with the recovery `CLOSE(scope)` started at once; an unknown outcome is reconciled from postdating evidence and becomes a gap if the protection is not working. An unknown amend or attach is never resubmitted through the close retry path; the port's next re-issue supplies it. The listener chooses `ATTACH` versus `AMEND` from `expected_protection[fill]` (empty → attach), not from the daemon's label, because the port emits one `BracketAmend` shape for both.

**Invariants.** **I1** — an `UNKNOWN` in any state an action reads refuses every risk-adding action. Risk-reducing requests remain admissible; broker dispatch still obeys the operation-identity, scope, evidence-currency and reconciliation rules of the primitives, so admission never means guessing a target or duplicating an unresolved send. **I2** — only broker evidence moves `P`, `W`, `pending` past `accepted`, `ledger.confirmed`, the *working* status inside `expected_protection` and any adapter position state; intent moves `pending` to `sent`, takes a reservation and records the **intended** protection, nothing else. **I3** — every block is sticky across restarts and cleared only by its owner's confirmed completion. **I4** — exactly one authority computes a broker quantity for a risk-adding order: the listener's sizing host (R-Q); `OrderIntent.qty` on `entry`/`add` is the **adapter-normal** quantity (a positive int, as the delivered constructor requires) and reaches the listener as `qty_normal`; a broker quantity travels only on `exit`/`flat`. **I5** — a checkpoint and its execution cursor are one atomic write; an event id is applied at most once. **I6** — the listener's `blocks` make any daemon emission inert; daemon quiescence is a second layer, never the safety property. **I7 (rev 5.3)** — every admitted protection transition preserves **the protection the strategy has defined** for the remaining position continuously, including between broker events, and cannot leave an executable orphan that opens reverse exposure: `AMEND` changes protection atomically, `ATTACH` adds it atomically, `CLOSE` reduces position and protection together. A lot the port has not yet protected (a bare Striker base before its first amend) is qualified behaviour, not a gap; from the moment the port defines protection, its absence from fresh `W` is a `protection_gap` — an incident requiring the durable recovery above, not a permitted transient state or a promise that recovery always succeeds. The rail never adds protection the port did not define. **I8 (rev 5.3)** — the rail executes only the semantics the emulator qualified: (i) resting stop entries filled intrabar; (ii) protection per lot exactly as the port defines it — attached at entry when the intent carries a bracket, otherwise attached by the port's first amend, re-issued per bar and taking effect from the next bar's path, **except** that for `orders_on_close` legs a newly issued fixed stop/limit already crossed by the generating close fills at that close (`_evaluate_at_close`), which the rail realizes as a market `exit` for that scope at the signal — the emulator's own rule evaluated on the bar the daemon already holds, not a new exit rule; (iii) trailing exactly as the port's `Bracket` parameters define it, realized by a native trailing stop (activation at fill ± activation ticks, then the traded extreme ∓ offset, effective stop the tighter of fixed and trailing); (iv) market orders at the signal. Two deviation classes are accepted, both measured in Phase 8 execution parity against frozen tolerances (`OWED-BY: TB-F1`): **latency** (an order reaches the broker seconds after the bar close instead of at `THIS_CLOSE`/`NEXT_OPEN`) and the **fill-path** class (the emulator's intrabar path assumption versus actual ticks for stops and trails — the TV-versus-live gap already inherent to the parity evidence). A semantic substitute — a daemon-held stop, a daemon-evaluated intrabar stop, a synthesized trail, protection on a lot the port left bare — is a different strategy and is never built. The separately ratified S6 emergency flats are operational risk-reduction exceptions, not claims of replay parity; the daemon-emitted one is authorized by §5 (3), the listener-side one by this spec (R-2).

## §2 — Event sequences (component · state read/written · fail-closed outcome; TB-I3 drives each sequence end to end through the simulated broker and asserts every transition — test `test_seq_s<n>_*`; the concrete cases are §2d)

**S1 — market entry / add** (Aegis, Striker, Vanguard entry and add, ORB add). (1) adapter `on_bar` → `OrderIntent(kind, side, qty=<adapter-normal quantity>, bracket=<the port's bracket or None>)` (positive int; adapter units — R-P) [daemon; adapter state only]. (2) barrier collects the bar's completion events and releases in the RC-5 order [`barrier.py`]. (3) `emit_risk_add` [daemon; control read older than one bar or unreadable → no risk-add emission, `control_read_failed`; risk-reducing emissions are gated only by `emit_risk_reducing`]. (4) B1 payload `{leg_id, signal_type, bar_time, close, stop_dist_pts, side, qty_normal, stop_loss?, take_profit?, trail_activation_ticks?, trail_offset_ticks?}` — bracket fields **only when the intent carries a bracket**; **no `qty`** [`b1_payload.py` maps `OrderIntent.qty` → `qty_normal`; a `sell` to open for an Equity-Index leg is refused at build]. (5) listener admission in this order: test identity → `blocks` (any member → `policy_block`) → arming expiry → side vs `allowed_entry_side` and the hedging bar → dedupe (TB-I4) → lifecycle (`watch_tiers_zero`) → `mode` (`settled_date` ≠ prior venue session → halt) → quantity law (R-Q, exact rational, from `qty_normal`) → capacity (refuse-never-clip; Aegis may enter S10) → `L2` per the leg's declared protection cases (`LEG_MAP.protection_cases`, mirrored from the port's declaration): `bracket_at_entry` → (b), `bare_entry` → (f), `trailing` → (g), and (c), (d), (e) for every leg — any item not `supported` refuses the entry (`l2_refused`), independently of the daemon's boot-time check [listener; writes `pending=sent` + reservation **before** send]. (6) send with the attached bracket fields when present (`dry_run` → never) → `SendResult` [`pending=accepted`]. (7) broker evidence: fill / partial / reject; the intended bracket recorded at admission is checked against postdating `W`: components working (`attached_to` = the entry order) are marked so; an intended component absent from `W` within one bar of the fill is a `protection_gap` → recovery `CLOSE(fill)`; a bare fill has an empty intended set and is not a gap [`pending`, `P`, `W`, `ledger.confirmed`; the reservation is released on reject or cancel acknowledgement, converted on fill, and **held** while the outcome is unknown]. (8) `ExecutionEvent` served at `/executions?since=<cursor>` → adapter `on_execution` (the adapter learns the **executed** quantity here and sizes its exits from it) → checkpoint + cursor [daemon, atomic]. **Cuts:** no evidence within one bar → `pending=UNKNOWN`, reservation held, `blocks += unknown_order` — account-wide, because every admission reads the ledger that holds the unresolved reservation (I1) — until order-level postdating evidence (the terminal event, or `W` absence plus consistent `P`) resolves it.

**S2 — ORB stop entry (one branch).** Step 4 carries `stop_price` and the port's bracket (ORB's carries trailing parameters); step 5 admits the risk-add at the stop's quantity and holds the reservation while it rests; the listener sends `order_type=stop` with the bracket fields (`L2(a)`, `L2(b)`, `L2(g)` must be `supported`); `W[MNQ]` gains the order on evidence; it fills intrabar when crossed, exactly as the emulator fills it; a resting entry older than one bar is cancelled (RC-9, cancel acknowledgement releases the reservation) unless re-issued; a fill continues at S1 (7). The buy-only ORB port (D-B7) emits one resting entry per day, so two OCA siblings are never live; daemon-side OCA is not built (test: never two resting entries for one leg). **No fallback:** if `L2(a)` is not `supported`, the registry refuses to run the ORB leg and the live packet is `BLOCKED — capability-problem` (a market entry after the crossing bar closes is a different strategy from the qualified one — I8; D-B4 allows no substitute book).

**S3 — protection exactly as the port defines it (one branch per case).** (a) *Bracket at entry:* an intent with `bracket` set → the bracket rides the entry send (`L2(b)`) and `W` gains the protective orders **with the fill**. (b) *Bare entry, first protection later (Striker):* an intent with `bracket=None` fills bare — qualified behaviour (I8) — and the port's first `BracketAmend` for that lot becomes **`ATTACH`** (`L2(f)`): protection linked to the position from that moment; until then the lot is protected only by the EOD, kill, feed-loss and daemon-loss closes, exactly as in replay it is protected by nothing. (c) *Per-bar re-issue:* the ports re-issue their exit levels every bar as Pine re-calls `strategy.exit`; live that is **`AMEND`** per closed bar (`L2(c)`), applied at the broker seconds after the close, which the emulator models as the new level taking effect from the next bar's path (latency class). (d) *Close-time crossed level (`orders_on_close` legs, e.g. Striker):* when the port's newly issued **fixed** stop or limit is already crossed by the generating bar's close, the emulator fills the exit at that close; the **daemon** applies the same rule on the bar it already holds and emits a market `exit` for that scope (reason `stop_close` / `limit_close`) instead of the amend; the listener runs `CLOSE(fill scope)` (latency class). An active native trail already through the close has executed at the broker intrabar, so no close-time trailing evaluation exists or is needed. (e) *Trailing:* the port's `trail_activation_ticks` / `trail_offset_ticks` travel in the bracket fields and are realized natively (`L2(g)`), OCO-linked with the fixed components; per-bar re-issue modifies only changed components, so an active trail's anchor is preserved exactly as the emulator preserves `trail_active` / `trail_extreme` across a bracket replacement; the daemon never tracks extremes. A tightening `AMEND` is risk-reducing (admitted under blocks, timeouts, late arrival); a loosening one is risk-adding (refused under any block). Rejection, unknown outcome and recovery follow the primitives (§1); sequential cancel/replace is never used. **No fallback:** a leg whose port uses a case whose `L2` item is not `supported` is refused at the registry and the live packet is `BLOCKED — capability-problem`; a daemon-evaluated intrabar stop, a synthesized trail or a bracket the port did not define is not the qualified strategy.

**S4 — cancel.** `cancel(order_ref)` from the adapter (ORB adds at a mode change through `set_mode`; stale resting entries) → the listener reads `pending[order_ref].kind` and fresh `W`: resting entry/add → risk-reducing → send, require the broker cancel acknowledgement, release the reservation; a resting entry/add with `pending = UNKNOWN` → the cancel is still sent (risk-reducing) and the acknowledgement or a "not working" reply is reconciled with postdating evidence before the reservation is released; protective → refused outside `CLOSE`/`AMEND` unless its position is `CONFIRMED(0)` on postdating evidence (orphan removal, risk-reducing); unknown ref → refused + alert.

**S5 — scoped exit / flat.** `exit` carries `qty` = the adapter's confirmed open quantity in scope (learned from fills, never from intent); the listener clamps `qty` **down** to the leg's confirmed allocation (never up; `exit_qty_clamped`) and runs **`CLOSE(fill scope)`**, which uses the verified `L2(d)`/`L2(e)` atomic reduction: protection remains effective for any unclosed remainder after each partial fill and is removed only when that scope is flat. Merely requesting a whole-fill close does not prove these properties; they require route evidence and partial-fill tests. A quantity-bounded close completes when the requested quantity is confirmed closed and the residual's protection is working at the intended parameters; a protection operation whose scope is confirmed consumed (the lot exited) completes as consumed. `flat` = `CLOSE(leg)`. Both are risk-reducing (admitted under every block, timeout and late arrival). Fill → `P`, `W`, `expected_protection`, `ledger`, `ExecutionEvent`.

**S6 — barrier timeout, late arrival, unhealthy source.** One source stale (S2b staleness formula, `2 × bar_period + 30 s`) or one leg silent past the barrier timeout (one bar period + 30 s): the barrier releases the bar with only its risk-reducing actions; every risk-add of every leg is refused for that bar (`barrier_timeout`); a late risk-reducing arrival for a closed bar is admitted, a late risk-add refused; the leg on the stale source emits nothing until its bar arrives, **with one exception — the feed-loss flat:** a leg whose source stays unhealthy past the staleness window and whose symbol is **not `CONFIRMED(0)` with `W` confirmed empty** (a confirmed non-zero or unknown position, or any working order — a resting entry must not trigger after its source has failed) receives one daemon `flat` intent (`feed_loss_flat`) per feed-loss episode; the listener cancels the leg's resting risk-adds and durably owns the resulting `CLOSE(leg)` through completion, including when the daemon stops or the position quantity is unknown. This timer is independent of new bar arrivals; transport redelivery uses the same operation identity and cannot initiate a second close. **Daemon-loss flat (listener-side; ratification item R-2):** the daemon cannot emit the feed-loss flat if it is itself down, so the listener persists the time of every control read (`last_control_read`, R-N) and, when no control read has arrived for longer than the staleness window while any owned symbol is not `CONFIRMED(0)` with `W` confirmed empty, cancels that symbol's resting risk-adds and runs `CLOSE(symbol)` for each such symbol (`daemon_loss_flat`), owning it durably like any other operation; after a listener restart the persisted timestamp is restored **before** this evaluation, and an absent timestamp counts as expired, so restarts cannot extend the window. This is a listener action outside the S2b Fail-closed row (which governs daemon emission) and is ratified with this spec, not by §5. Rationale: the strategy's exit logic cannot run without bars, and a resting bracket alone is not the qualified exit set; the flats are live-only, risk-reducing, and the replay has no counterpart (recorded as such). Both set the session-scoped `feed` block (R-1). **The daemon-emitted flat is the exact signal §5 (3) authorizes; until the addendum is ratified the S2b Fail-closed row governs and TB-I3 must not implement it.**

**S7 — EOD.** At the buffer (16:30 ET regular, 12:44 ET early close; an overlay date blocks the whole session): (1) `blocks += eod`; (2) cancel every resting `entry`/`add` across legs, broker acknowledgements required; (3) **prepare `CLOSE(symbol)` for every owned symbol** (`prepared_at` = the buffer instant) and send it for every symbol not shown `CONFIRMED(0)` with no attached orders on evidence that postdates `prepared_at` — a pre-buffer snapshot, however fresh, never skips a symbol, because a resting entry can fill between that snapshot and the buffer (AC-8); the primitive handles the symbol's protective orders through verified `L2(d)`/`L2(e)` atomic reduction — never a bare `closeposition` beside standing standalone stops; (4) confirm `P = CONFIRMED(0)` on every owned symbol from evidence that postdates step (3)'s `prepared_at`; (5) confirm `W = ∅` on every symbol from the same evidence, cancelling any orphan (acknowledgements); (6) settle `mode` (R-L), reset per-day state; `eod` clears at the next session open. Any failed, partial, rejected, unknown or timed-out step leaves `eod` set, retains per-day state, reports the exposure and alerts. Steps run only in this order.

**S8 — kill switch (operator).** `c1_rail_arm.py --kill`: (1) `blocks += kill` on the listener volume **first** — from this instant every risk-adding admission is refused whatever the daemon does (I6); (2) the control endpoint (R-N) serves `kill=true`, so a running daemon's next control read drops `emit_risk_add` and it stops emitting risk-adds (`emit_risk_reducing` is unaffected: its exits, flats, cancels and tightening amends are still emitted and admitted); (3)–(5) = S7 (2)–(5), postdating evidence included; (6) `--disarm` — applied by the listener as part of the completion transition itself (the evidence that completes the last kill close sets `dry_run=true`), never dependent on a later status call; (7) **daemon-app acknowledgement:** the operator sets `emit_enabled=false` in the daemon's `/data` config on the separate Fly app (`fly ssh console` + the atomic config write `m1_stage1_control.py` already uses) and runs `--kill-status`, which records `daemon_control: acknowledged | not_reached` from the daemon's `GET /` heartbeat. **Completion** = `P = CONFIRMED(0)` and `W = ∅` on every owned symbol on postdating evidence, and disarmed; the acknowledgement is reported beside it and its absence is an open alert, not a reason to withhold "flat" (step 1 already makes any emission inert). Callable with the daemon down (steps 1 and 3–6 need only the listener); a failed/partial/unknown close leaves `kill` set and reports the remaining exposure; `kill` clears only by the operator after confirmed flatness. Recorded as an `arming_deviation`-class ledger event (`kill_switch`); never automatic on a signal; the O-1 beta-death event routes here as an operator action, not a multiplier.

**S9 — crash and restart (cut at every S1 step and every protection-operation send/outcome boundary).** *Listener:* restore `operations`, `expected_protection` and `last_control_read` first; resume/reconcile each unresolved `CLOSE`/`AMEND`/`ATTACH` using its original identity before any overlapping dispatch; never infer that a missing acknowledgement means no execution. Then rebuild `ledger` from `ExecutionStateStore` + `pending`; `blocks += restart_unreconciled`; require `P` **and** `W` `CONFIRMED` for every owned symbol through R-M (L-1) on evidence that postdates the restart; reconcile `pending` against `W`: an order in `W` absent from `pending` (orphan), or in `pending` as `sent`/`accepted` but absent from `W`, halts that leg with `restart_orphan_order` and an alert; **an orphan of unknown kind is never auto-cancelled** (it may be protection); a position whose `expected_protection` names an order absent from `W` is a `protection_gap` → recovery `CLOSE(symbol)`; a bare lot with an empty expected set is not a gap; the block clears only on a PASS reconciliation. *Daemon:* restore each adapter from its checkpoint, resume the cursor, consume outstanding events, then compare the adapter's open fills, its per-fill defined brackets and resting intents with `P` and `W` for its symbol; mismatch → that leg halts; no checkpoint → cold start holds emission for TB-W1's counts. A crash between S1 (6) and (7) leaves `pending=UNKNOWN` with its reservation held until evidence; between (7) and (8) the event is re-served from the cursor and applied once (I5).

**S10 — capacity takeover (Aegis, D-B8).** Under `blocks = ∅`: cancel every displaced resting **or partially filled** entry/add, counting a cancel only when evidence shows the order terminal (a route's accept of the request is not confirmation) → **`CLOSE(symbol)`** per displaced symbol → `P = CONFIRMED(0)` and the symbol's `W` empty on each, on postdating evidence → reconcile → admit Aegis; any unacknowledged cancel or partial/rejected/unknown/timed-out close refuses Aegis and leaves the displaced legs as they are (never half-closed): an unresolved close is `unknown_order`, an expected protective order missing after reconciliation is `protection_gap`, each cleared by its owner; no separate capacity block exists. Under O-5/O-6 the protected Striker ceiling is 77 micro-equivalents, so the protected path is reachable and tested.

### §2e — Executable reference (PR #365) and the review contract

`tests/ops/tb_s3_kernel/` (broker, kernel, daemon, harness) is the **executable reference** for §1 and §2d: the state table with one writer per state, the blocks, `CLOSE`/`AMEND`/`ATTACH`, evidence currency, L-2 gating, the emission gates and the feed-loss / daemon-loss timers, against a route whose only capabilities are L-2 (a)–(g), with reject / unknown / partial injection. `test_tb_s3_kernel_model.py` encodes AC-1..AC-10, `test_tb_s3_kernel_findings.py` one scenario per review-finding class on this spec, `test_tb_s3_kernel_review.py` the model's own review round. Where this prose and the model disagree, the disagreement is a defect in one of them to be fixed in both, never a licence to implement either alone. **Review contract (from rev 5.5):** a finding on §1 or §2 is accepted only with a reproducing scenario against the model — if it fails, model and spec change together; if it passes, the finding is a wording or coverage gap, closed by a wording fix or a new scenario. Findings on §3 rows outside the model's declared scope (sizing laws, barrier order, calendars and overlay, settled mode, dedupe, adapters and checkpoints, the arm interlock) follow the ordinary fold. **TB-I3's gate:** the real listener and daemon pass the model's scenarios through a harness of the same shape (same inputs, evidence and expected states), in addition to the sequence tests named in §3.
