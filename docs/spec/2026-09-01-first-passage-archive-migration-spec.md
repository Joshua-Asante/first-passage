   ```bash
   git checkout --orphan from-first-passage-hygiene-stub
   git rm -rf .
   printf '# from-first-passage hygiene migration\n\nSee first-passage:docs/spec/2026-09-01-first-passage-archive-migration-spec.md\n' > README.md

   ```
   This branch is never merged into archive's own `main` (histories share no common ancestor; confirmed `git merge-base` empty against `pre-prune-2026-08-08`) and becomes the **standing base** every subsequent cluster lands onto (step 5).
3. **Precondition for the `lab/archive/` cluster specifically:** `scripts/archive_lab_analysis.py:618-630` only emits a catalog row when both the local `CARD.md` stub and the local `lab/archive/<slug>/` directory exist (confirmed by reading the source) — deleting the directory silently drops the row even though the stub still points readers at it. Per migration cluster, extract history via `git filter-repo` against a disposable local clone (never the live worktree) — verified: `lab/archive/` (618 files, 4,254 reachable commits) extracted in 7.9s with `--path lab/archive/`. `git subtree split` is not viable here — timed out 3× (up to 3min) even on a 4-file dir. Windows note: clone destination needs `core.longpaths=true` + a short path, or checkout fails on deep archive paths (`Filename too long`, reproduced and fixed this session).
   - **Renames require BOTH paths, not `--path-rename` alone.** `--path-rename old:new` is a transformation, not a filter — per `git-filter-repo`'s own docs, without an accompanying `--path` selector it keeps the *entire* repo and just renames matching paths, importing all of `first-passage` history into a supposedly isolated cluster branch. The correct invocation for a moved campaign (confirmed pattern: `msl_c3_m2k_2026-08` moved `lab/analysis/c1/msl_c3_m2k_2026-08/` → `lab/archive/msl_c3_m2k_2026-08/` at archival time) is:
     ```bash
     git filter-repo --path lab/analysis/c1/msl_c3_m2k_2026-08 --path lab/archive/msl_c3_m2k_2026-08 \
       --path-rename lab/analysis/c1/msl_c3_m2k_2026-08:lab/archive/msl_c3_m2k_2026-08
     ```
     The manifest's `lab/archive/` section records recovered pre-rename paths for the SAFE slugs where evidence exists; for the rest, `git log --follow` is uninformative repo-wide (history starts at the single 2026-08-14 public-release squash commit) — treat as flat-origin (single `--path lab/archive/<slug>` is correct) unless a citation says otherwise.

   ```bash
   git checkout -b cluster-<slug> from-first-passage/hygiene-2026-09
   git remote add cluster-source <path-to-step-4-filtered-clone>
   git fetch cluster-source
   git merge --allow-unrelated-histories cluster-source/master -m "Merge <slug> extracted history"
   git push archive cluster-<slug>
   ```
