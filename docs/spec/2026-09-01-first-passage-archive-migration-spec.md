Steps:
1. Operator un-archives `first-passage-archive` (currently GitHub-archived/read-only) and confirms push access; the `archive` remote is already configured locally in the primary `first-passage` checkout (a *fresh* clone of `first-passage-archive`, as used in step 5, gets `origin` instead — see that step).
2. Create the persistent migration base **once**, before any cluster work, as a true orphan commit — not `HEAD` of the current checkout:
   ```bash
   git checkout --orphan from-first-passage-hygiene-stub
   git rm -rf .
   printf '# from-first-passage hygiene migration\n\nSee first-passage:docs/spec/2026-09-01-first-passage-archive-migration-spec.md\n' > README.md
   git add README.md
   git commit -m "Initial base for first-passage hygiene migration"
   git push archive from-first-passage-hygiene-stub:refs/heads/from-first-passage/hygiene-2026-09
   ```
   This branch is never merged into archive's own `main` (histories share no common ancestor; confirmed `git merge-base` empty against `pre-prune-2026-08-08`) and becomes the **standing base** every subsequent cluster lands onto (step 5). **Tested end-to-end 2026-09-01** in disposable local repos (bare "fake-archive" + orphan-commit stub + a synthetic unrelated-history "cluster-source" repo) — the full sequence through step 5 completed with exit 0 and produced a genuinely mergeable-by-ordinary-PR branch.
3. **Precondition for the `lab/archive/` cluster specifically:** `scripts/archive_lab_analysis.py:618-630` only emits a catalog row when both the local `CARD.md` stub and the local `lab/archive/<slug>/` directory exist (confirmed by reading the source) — deleting the directory silently drops the row even though the stub still points readers at it. Before the first `lab/archive/` deletion PR, extend that script to recognize an external-body state (e.g. a `Body: first-passage-archive:<path>` marker in the stub, in place of requiring local directory presence) and add a test asserting the catalog still lists an externally-archived campaign. `lab-catalog` must stay green for the right reason, not because the row silently vanished.
4. Per migration cluster, extract history via `git filter-repo` against a disposable local clone (never the live worktree) — verified: `lab/archive/` (618 files, 4,254 reachable commits) extracted in 7.9s with `--path lab/archive/`. `git subtree split` is not viable here — timed out 3× (up to 3min) even on a 4-file dir. Windows note: clone destination needs `core.longpaths=true` + a short path, or checkout fails on deep archive paths (`Filename too long`, reproduced and fixed this session).
   - **Renames require BOTH paths, not `--path-rename` alone.** `--path-rename old:new` is a transformation, not a filter — per `git-filter-repo`'s own docs, without an accompanying `--path` selector it keeps the *entire* repo and just renames matching paths, importing all of `first-passage` history into a supposedly isolated cluster branch. The correct invocation for a moved campaign (confirmed pattern: `msl_c3_m2k_2026-08` moved `lab/analysis/c1/msl_c3_m2k_2026-08/` → `lab/archive/msl_c3_m2k_2026-08/` at archival time) is:
     ```bash
     git filter-repo --path lab/analysis/c1/msl_c3_m2k_2026-08 --path lab/archive/msl_c3_m2k_2026-08 \
       --path-rename lab/analysis/c1/msl_c3_m2k_2026-08:lab/archive/msl_c3_m2k_2026-08
     ```
     The manifest's `lab/archive/` section records recovered pre-rename paths for the SAFE slugs where evidence exists; for the rest, `git log --follow` is uninformative repo-wide (history starts at the single 2026-08-14 public-release squash commit) — treat as flat-origin (single `--path lab/archive/<slug>` is correct) unless a citation says otherwise.
   - **`git filter-repo`'s default output branch is `main`**, matching `first-passage`'s own default branch (confirmed via `gh api`) — not `master`. Step 5 fetches this branch by name; do not hardcode `master`.
5. **Attach each extracted cluster to the migration base.** The filtered clone's history (step 4) and `from-first-passage/hygiene-2026-09` (step 2) share no common ancestor by construction — an ordinary PR cannot merge them directly. Work from a **fresh `git clone` of `first-passage-archive`** (its default remote is `origin`, not `archive` — that name is specific to the second remote configured in the *original* `first-passage` checkout in step 1, and is not inherited by a new clone):
   ```bash
   git clone <first-passage-archive-url> archive-work && cd archive-work
   git checkout from-first-passage/hygiene-2026-09
   git checkout -b cluster-<slug>
   git remote add cluster-source <path-to-step-4-filtered-clone>
   git fetch cluster-source
   git merge --allow-unrelated-histories cluster-source/main -m "Merge <slug> extracted history"
   git push origin cluster-<slug>
   ```
   Then open the PR `cluster-<slug>` → `from-first-passage/hygiene-2026-09` inside the archive repo — this one **is** an ordinary PR, since both branches now share the merge commit as a common ancestor (verified via `git merge-base` in the disposable-repo test — non-empty). **The PR must be merged with the "Create a merge commit" method, never squash or rebase** — a squash merge collapses the filtered history into one snapshot commit and the extracted commit-by-commit history (the entire point of step 4) becomes unreachable garbage once the temporary `cluster-<slug>` branch is deleted, while every gate in this spec would still report green. Stage clusters in order of how clean each is (see [the manifest](2026-09-01-first-passage-archive-migration-manifest.md) for the explicit SAFE list, exclusion counts, and reasoning per cluster): `docs/briefs/*.md` root (60/64) and `docs/briefs/pre-registration/` (42/88) first, then `lab/archive/` (33/90), `docs/notes/audits/`+`research/` (33/66), `docs/superpowers/plans/` (14/24), `docs/spec/` (9/21), `docs/briefs/handoffs/`+`docs/historical/` (16/40), then `docs/notes/notice/`'s single file. Do **not** touch the eight entirely-excluded clusters (`lab/analysis/c1/`, `lab/analysis/legacy/`, `lab/analysis/harvest/`, `lab/analysis/_inbox/`, `docs/briefs/closures/`, `docs/briefs/rnd-pipeline/`, `docs/notes/notice/` as a batch, `docs/analytics/`+`lessons/`+`methodology/archive/`+`external/`) without a fresh, separately-scoped decision — the manifest's exclusion is structural, not a per-file judgment call that individual re-triage can overturn.
