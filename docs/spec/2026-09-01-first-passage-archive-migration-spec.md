# SPEC: first-passage → first-passage-archive migration (Levels 1–3, full pattern completion)
Status: PROPOSED · 2026-09-01 · authorizes nothing ($0 · K=0) · depends: operator un-archives `first-passage-archive` on GitHub
Objective: relocate ~1,507 closed-research / spent-process files (enumerated at cluster granularity in [`the manifest`](2026-09-01-first-passage-archive-migration-manifest.md)) from the public `first-passage` tree into the private `first-passage-archive` repo, preserving retrievability and every live citation.

Steps:
1. Operator un-archives `first-passage-archive` (currently GitHub-archived/read-only) and confirms push access; the `archive` remote is already configured locally.
2. Create the persistent migration base **once**, before any cluster work: push an initial commit (README stub is enough) to a new branch `from-first-passage/hygiene-2026-09` in `first-passage-archive` via a direct `git push archive HEAD:refs/heads/from-first-passage/hygiene-2026-09` — no PR, since a brand-new branch has no base to review against. This branch is never merged into archive's own `main` (histories share no common ancestor; confirmed `git merge-base` empty against `pre-prune-2026-08-08`) and becomes the **standing base** every subsequent cluster PR targets with `--base from-first-passage/hygiene-2026-09` (short-lived feature branch → PR → merge into that base, inside the archive repo).
3. **Precondition for any `lab/archive/` cluster specifically:** `scripts/archive_lab_analysis.py:618-630` only emits a catalog row when both the local `CARD.md` stub and the local `lab/archive/<slug>/` directory exist (confirmed by reading the source) — deleting the directory silently drops the row even though the stub still points readers at it. Before the first `lab/archive/` deletion PR, extend that script to recognize an external-body state (e.g. a `Body: first-passage-archive:<path>` marker in the stub, in place of requiring local directory presence) and add a test asserting the catalog still lists an externally-archived campaign. `lab-catalog` must stay green for the right reason, not because the row silently vanished.
4. Per migration cluster, extract history via `git filter-repo --path <dir>` against a disposable local clone (never the live worktree) — verified: `lab/archive/` (618 files, 4,254 reachable commits) extracted in 7.9s. `git subtree split` is not viable here — timed out 3× (up to 3min) even on a 4-file dir. Windows note: clone destination needs `core.longpaths=true` + a short path, or checkout fails on deep archive paths (`Filename too long`, reproduced and fixed this session). **`filter-repo` does not follow renames** — any campaign that moved into its current location (confirmed pattern this session: `msl_c3_m2k_2026-08` moved `lab/analysis/c1/msl_c3_m2k_2026-08/` → `lab/archive/msl_c3_m2k_2026-08/` at archival time) needs its pre-move path passed too (`--path <old> --path <new>`, or `--path-rename old:new`), or the extraction only proves post-move history. Check each cluster's origin via `lab/CATALOG.md`'s archived-date annotation before running the single-path extraction.
5. Before any Level-3 link rewrite, run the enumeration command in [`the manifest`](2026-09-01-first-passage-archive-migration-manifest.md#level-3--needs-engineering-before-it-can-move-607-files) fresh (not the survey-era ~150 estimate) for the 56 previously-uncited-looking `lab/archive/` campaigns cited from `ops/instruments/*.md` and `docs/rejected_candidates.md`, and fix each pointer to the new cross-repo location (format TBD at execution — proposed: mirror the existing CARD.md `Body:` pointer style) in the *same* PR as the deletion.
6. Stage as sequential PRs, one per cluster (see [the manifest](2026-09-01-first-passage-archive-migration-manifest.md) for the full cluster list, exclusions, and per-cluster verify commands), ordered by risk: Level 1 first to prove the pipeline end-to-end → Level 2 clusters → Level 3. Each cluster PR: (a) merge its content into `from-first-passage/hygiene-2026-09` in the archive repo first (step 2's base), (b) then open a *separate* PR against `first-passage`'s `main` deleting the source + rewriting any citing pointers, gated on `check_adr_graph.py` / the relevant `pytest` subset / `lab-catalog` / a dead-link grep.
7. Before each `first-passage` deletion PR, tag HEAD as `pre-hygiene-migration-<date>-<cluster-slug>` (cluster slug required — same-date tags collide otherwise, e.g. two clusters landing 2026-09-05 would both attempt `pre-hygiene-migration-2026-09-05` and either fail or silently overwrite the earlier snapshot) as a local fallback; independently verify the archive branch's content before the corresponding deletion lands.

Gate: RESOLVED if all 3 levels land, the archive branch's content verifies byte-identical to what was deleted at push time, `lab-catalog` stays green for a real reason (not a silently-dropped row), and every PR in the sequence passes its gate battery with zero HARD findings; FALSIFIED if `first-passage-archive` cannot be un-archived, or the filter-repo/longpaths/rename workaround fails against a real (non-disposable) cluster extraction.
Boundary: no `core/`, `dd_protection`/`firm_rules`, or Pine touched; no move of any cluster/file listed under "What stays public" in [the manifest](2026-09-01-first-passage-archive-migration-manifest.md#what-stays-public-regardless-of-level-do-not-move-under-any-circumstance); `first-passage`'s visibility/branch-protection settings untouched; `first-passage-archive`'s existing branches and `main` untouched (new branch only, never a force-push).
