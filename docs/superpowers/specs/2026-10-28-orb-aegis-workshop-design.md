# ORB + Aegis human-led research workshop

**Status: proposed for Joshua and Claude review, 2026-10-28.** This is the owner
of this workflow proposal, not an amendment to a strategy, campaign or release.
The companion [workshop kit](2026-10-28-orb-aegis-workshop-kit.md) contains the
pilot card, trial template and synthetic acceptance walkthrough.

## Question and decision

Can Joshua's hypothesis selection and visual diagnosis shorten the time to a
defensible research decision while agents preserve reproducibility and catch
errors? Decide whether to adopt a small attended workflow, revise it, or stop.
More trials per hour alone does not answer that question.

This PR designs the process only. A later workshop needs its own bound surface,
question, permissions and budget. Parameter campaigns, protected historical or
strategy-source reads, simulations, platform/Sim/broker orders, account changes,
spend, infrastructure and deployments require their separately applicable grants.

## Smallest useful interaction surface

Use one Markdown session card, one append-only trial log and existing result
exports. Joshua sees a short status strip: question, control identity, draft versus
applied delta, remaining attention/compute/trial allowance, last valid comparison,
integrity warnings and next decision. He changes one draft factor or chooses a
comparison; the agent reads back the exact applied settings before dispatch.

| Approach | Benefit | Cost / decision |
|---|---|---|
| Worksheet + existing CLI/export | Usable without new infrastructure; easy to inspect and review | Recommended first; manual capture must pass the pilot |
| Existing notebook or attended UI | Faster visual diagnosis if the bound surface already supports it | Use only with reproducible exports and captured actual settings |
| New dashboard | Could reduce copy errors and feedback delay | Defer; measure a concrete pilot bottleneck before proposing a minimal read-only summary plus draft editor |

No generic agent orchestration framework. The existing private ORB runner repair
does not establish workshop admission: capacity/release is held. Its coordinator
must admit any reuse; this specification does not invoke it or promise latency.
The bound tool/version, command/export method and measured feedback delay belong
on the later card. A missing export is a blocker to a matched result, not a reason
to reconstruct settings from memory.

## Roles and session lifecycle

Joshua selects the mechanism question, interprets plots and chooses draft changes.
These are plausible human advantages, to be measured rather than assumed. One
named session owner resolves scope and hands off to the existing campaign owner.
One agent is the sole writer/dispatcher and automates IDs, setting capture,
integrity checks, aggregation and budget accounting. An independent reviewer
reads a pinned package and returns findings without writing to the trial branch.
Human override is a recorded decision; it cannot waive locked parameters,
permissions, source fidelity or a confirmation protocol.

1. **Bind:** record the card fields in the kit, freeze the control, inventory prior
   data exposure, and agree the question, comparison, action map and stop bounds.
   Unknown fidelity is `unmatched/diagnostic-only`; stop claims requiring matching.
2. **Draft:** Joshua names the hypothesis, delta and reason. The writer allocates a
   trial ID *before* applying anything, records its parent and exposed information,
   then prepares the comparison and cost model. Log abandoned drafts too.
3. **Check:** read actual resolved settings from the bound tool/export, compare
   with the requested delta and frozen control, and verify the approved surface,
   integer quantities, cost/fill model and remaining allowance. Missing fields
   block dispatch. Joshua acknowledges the readback; in-envelope choices then
   proceed under the workshop grant without repeated permission prompts.
4. **Run or observe:** persist `prepared -> running -> completed/failed/interrupted/
   uncertain`. A manual action producing an output is a trial even if no automated
   command ran. Capture actual settings again with result identity and timestamps.
   `completed` alone is not valid: source/config pins, complete output and integrity
   checks must agree. Failed variants stay in the denominator of workflow errors.
5. **Compare:** return the scorecard, uncertainty, path diagnostics and integrity
   status together. Joshua records `discard`, `refine`, `defer`, or `package for
   independent review`, with rationale and the next question. Do not quietly
   broaden bounds, change the control, or lower a threshold to keep iterating.
6. **Close:** freeze the log and package, reconcile every allocated ID and any
   remaining processes, record consumed budget and unresolved outcomes. Existing
   owners decide subsequent qualification or release.

**Interruptions and duplicate effects:** reserve a stable trial ID and an attempt
ID; persist command/config/output location before launch. After interruption, the
writer first checks the original process and output receipt. Adopt a verified
completed result once; otherwise retain `uncertain` and block its successor until
reconciled. A known failed attempt may retry with a new attempt ID, same trial
lineage and explicit reason. Never infer order/API idempotency from a research ID.
On owner/writer handoff, the old writer stops and the successor records custody
before mutation. Concurrent reading is fine; two dispatchers are not.

**Stop and undo:** Joshua can cancel an unapplied draft and record `abandoned`.
For an applied change, restore the frozen research configuration and verify its
actual digest. A running task receives a stop request; record observed termination
and partial outputs, or `uncertain`. Restoring settings does not erase results or
data exposure. Failure to restore blocks the next run. A scope/permission change,
holdout peek, exhausted bound or irreconcilable identity mismatch stops the session.

## Comparisons and scorecard

Begin with a few interpretable factors and a declared mechanism. Vary one factor,
then test an explicitly named interaction; a second strategy is not a license to
change entry, exits, sizing and protection simultaneously. When applicable compare
control/candidate ORB alone, Aegis alone and their pair on the same underlying
scenario IDs, chronology, horizon, starting state, rules and costs. Pin shared
randomness where relevant; estimate uncertainty of the paired difference rather
than subtracting independent confidence intervals. Record exclusions and missing
arms; without a supported expression the comparison remains partial.

Standalone and paired portfolios each evolve their own equity, peak, trailing
floor, orders, capacity and absorbing outcomes. Pair outcomes cannot be obtained
by summing standalone profits. Attribute rejected/skipped orders, integer size
rounding, overlaps and protection changes. A later breach diagnostic may cross a
protection history only under its owner's explicit protocol, retaining each path's
own floor/capacity/order state. Match evaluation and funded stages separately:
quantities, payout rules, qualifying days and headroom can differ. Never reuse a
fresh account result as the state of a used account.

Each valid comparison reports:

- The bound payout objective and horizon; pass, breach and unfinished counts with
  denominators (mutually exclusive at the declared evaluation stopping time).
  Funded transitions and later breaches use their own denominators and clocks.
- Modeled payout eligibility, request/approval/payment and landed receipt as
  separate events; modeled receipts are explicitly simulated, never actual cash.
- Net results after commission, spread/slippage, fill assumptions and applicable
  fees; uncertainty, dependence assumptions, small-sample limits and sensitivity.
- Exposure, margin/capacity use, minimum floor headroom, floor/peak path and
  rejected orders; headroom diagnostics use the same balance/floor clock.
- Joshua active minutes, agent/compute time, wall-clock feedback delay, rework and
  actual metered cost where available; estimates remain labeled estimates.

Use an event ledger: `event_id, scenario_id, stage, event_time, effective_time,
type, balance_delta, receivable_delta, cash_delta, fee_delta, evidence_ref`.
Request and approval alone create no landed cash. At debit, account balance falls
and the applicable entitlement/receivable changes; payment/receipt changes its
settlement stage, bank receipt increases landed cash and clears the receivable.
Denial, refund and forfeiture are explicit events. Record gross and split/fees
separately and identify the valuation horizon, including post-stop settlements.
Reconcile balance, entitlements and receipts without counting the same withdrawal
twice. Unknown debit/refund timing means cash valuation is unresolved; do not fill
it with an assumed lag. Synthetic arithmetic checks validate a convention, not the
venue contract or an expectation bound.

## Adaptive exploration and confirmation

Every viewed variant, chart-driven choice, abandoned setting, failed run and manual
trial enters the exposure/lineage log. Reusing observations to choose parameters is
selection even when Joshua does it quickly. Trial count describes exposure; it does
not correct adaptive-search bias or create an effective independent sample size.

Before reserving confirmation, inventory operator and agent exposure by dataset,
dates, outputs and inherited decisions, including uncertainty in the inventory.
If untouched observations cannot be justified, label confirmation unavailable;
choose a separately approved prospective collection or remain exploratory.
Before opening eligible confirmation data, freeze candidate/control identity,
metrics, cost assumptions, hypotheses, thresholds/action map, sample/horizon,
stopping/peeking rules and independent analysis owner. An unplanned peek contaminates
that partition; record it and stop confirmatory interpretation. Do not silently
replace the partition or relax thresholds. Any new design needs a new declaration.

Independent review checks provenance and mechanism before confirmation or native
qualification. Positive exploration motivates a test; non-significance is not
disproof. A selected policy's negative result does not exclude other policies.
If a null is later needed, define its information clock, dependence, admissible
policy class and valid inference first; this workflow adopts none from the audit.
Model output, offline test completion, coordinator acceptance and native host
acceptance remain distinct evidence levels.

## Evaluate the workflow and leave choices explicit

Use the kit's synthetic tasks to compare the current manual method and this
assisted method with equivalent task difficulty and recorded order/practice effects.
Pilot 1 tests capture and integrity overhead only; it does not test Joshua's
hypothesis selection or visual diagnosis. Passing it supports trying the recording
process, not adopting the full human-led research premise. A separately approved
later pilot must include plot-based diagnosis and hypothesis/comparison choices,
with matched tasks and a predeclared decision-quality rubric, before evaluating
those contributions. Existing plots or a simple static synthetic plot can suffice;
a notebook, dashboard or strategy experiment is not a prerequisite.

One pilot is descriptive. Measure time to a correctly supported decision, active
owner minutes, feedback latency, capture errors/omissions, duplicate dispatches,
reconciliation time and reviewer corrections. Decision quality means correct
identity, useful comparison, complete adverse evidence and an action justified by
the declared rule, scored independently on the same rubric. Trial throughput is a
secondary measure. Continue only if the predeclared pilot rule is met; extra logs
that add owner burden without improving decisions are a reason to simplify.

Open choices for Joshua/owners: exact executable ORB/Aegis expressions and permitted
surface; evaluation/funded vintage and objective versus account-preservation
constraint; acceptable attention/compute limits; which existing export is reliable;
whether eligible confirmation data exists. The pilot numbers in the kit are
unapproved options. Implementing a capture helper, UI or runner adapter is separate
work, justified only by a demonstrated gap after review.
