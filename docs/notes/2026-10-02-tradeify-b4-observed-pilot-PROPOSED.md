## Proposed end-to-end contract

**Integration owner:** Claude coordinator (3). One worker owns producer through G5 acceptance, after a frozen card and explicit dispatch. The statistical sampler, seed addresses, replay logic and decision formulas remain as implemented.

1. **Observe the existing pilot once.** Add a store-free `on_pilot_observed` callback to `_run_part_a`. Retain the actual ordered panel, sampled path and replay session identities from the already executed probe. Call it once only after the existing full-horizon and sampled-versus-replayed identity checks succeed, before statistical panel sampling. Do not reconstruct the observation from plan data or call a sampler/replay provider again to manufacture it. An incomplete replay or callback failure produces no B4-complete result.
2. **Canonical record.** Proposed schema `qualification_part_a_pilot_observation/v1`, closed keys: `schema`, `outer_source_session_ids`, `sampled_path`, `replayed_path`. Each ordered path row has exactly `occurrence`, `path_session_date`, `source_session_id`, using the existing path/replay types and canonical date encoding. Preserve duplicates and order; validate exact horizon counts and matching row triples. Outer membership uses actual panel order and multiplicity. Do not include private bars, strategy code, account values, salt or raw seed material.
3. **Transport and custody.** The compute adapter serializes the callback's data once using the existing canonical JSON encoder and exposes those bytes on `PartACompute.pilot_observation_bytes`. Missing or duplicate callback invocation refuses a successful worker return. The worker encoder embeds the parsed observation and its SHA-256 under the Part A pilot field, alongside the existing plan seed-input digests. No new standalone artifact role is proposed: the existing bounded worker payload and capture protocol retain the observation as part of the exact captured bytes. Its work/attempt/plan/source/runtime binding is the existing payload/attestation envelope, not caller-supplied duplicate identifiers.
4. **Bounds and ordering.** Enforce the existing output-byte ceiling over the complete encoded result and frame; apply strict list/count validation before G5 reconstruction. No increased ceiling or allowance is implicit. Observation serialization, validation and custody are included in the original metered invocation; pilot timing placement and its effect on the existing predictor must be explicitly checked in the measurement return. If the largest admitted observation cannot fit, return NEEDS_CONTEXT rather than truncate, hash away the observed membership, or enlarge the profile. The only B4-accepted durability point is finalized capture with exact bytes, exit facts and lifecycle evidence. A transient observation or readable partial frame is insufficient.
5. **Independent consumer.** G5 derives expected probe selection using admitted private source inputs and the existing probe addresses, independently of the worker record. It compares ordered outer membership, sampled path and replay association, verifies canonical bytes/digest and envelope bindings, then binds acceptance through the existing capture digest in the checkpoint assessment. It does not execute a second statistical trial or replay to fabricate evidence. Reconstructing selection is validation, not a second pilot. The worker's observed triples establish execution association under the protected-worker trust boundary; this does not claim independent instrumentation outside that boundary.
6. **Versioning and history.** Freeze the exact nested field shape and a versioned new worker-result contract before dispatch. New B4-required releases reject the old plan-only shape. Preserve byte-identical historical receipt inspection under its originating release; never upgrade an old capture to B4-complete or grant new authority to it. A changed release cannot borrow old measurement or capture acceptance.
7. **Interruption.** Before finalized capture, interruption leaves the existing terminal/custody rules in force, even if the callback ran. Complete capture permits existing validation/signing recovery without recomputing the pilot. This observation is not the complete statistical prefix used by H9 R2 / D3 recovery and does not widen recovery eligibility.
