## Review findings carried here, not folded into the ADR

Codex review of #584 at `e57bd98`; under the operator's round-limit rule these bite only at acceptance:

- **4162535532 (P2), §A12.4 table.** Bare bullet lines ended the table after the edition pre-registration row, detaching the later owners from their columns. Below, those bullets are joined into that row's cell; wording unchanged.
- **4162535544 (P2), D7 rationale.** D7's recommendation says the unanswered UB rows bind only option-B machinery or the editions. As written that is false: §A12 assigns UB-7 to F2's release classes and UB-5 to F4's partial-close reconciliation, and the held-request watch derives from deferred monitoring text. If the replacement is recommended, name the safeguards that make it safe (separate gate-C evidence, conservative defaults) instead of calling those rows irrelevant to the first release.
- **4162535551 (P1), D5 premise.** D5 relies on "Restoring evidence does not resume trading (halt/resume §3)". That does not hold for stale evidence. Halt/resume §4.1 O-1 leaves open whether stale order-level evidence is an incident; today's code refuses rather than halts; rail `pending` marker (5) stops automatic restoration only after an incident halt. Deferring rule 11 item 3 would let fresh evidence lift the refusal without reconciliation. The ADR now lists this in §A12.5: the choice between an explicit no-auto-resume rule and classifying stale evidence as an incident is owed at acceptance.

- **D2. F2's evidence classes, split** (reframed 2026-10-01 on the refute-first review of #584, P2-1):
  - **(i) Runtime classifier (T09):** keep §59 Ruling 7(b)(3)'s hold, so the release class is terminal-only. *Recommendation: keep.* This decides bookkeeping, not availability: a runtime release restores no authority.
  - **(ii) Attended recovery (halt/resume §3):** the existing owners govern (closure row 1, E3, halt/resume §4 ¶2, Gate A A3(iii)). The release class is what an accepted E3 producer can establish. **The only question for Joshua:** is 7(b)(3) also meant to reach attended recovery? If yes, a lost-response request has no first-release release path even once a producer exists. If no, that path opens when an accepted producer exists, which is already a live-release precondition. *Recommendation: no*, and decide the class when UB-7's evidence returns.
- **D3. F5 qualifies §A2 rule 6's premise.** A uniquely correlated effect transfers under F2 instead of being only an additional exposure. Rule 6 is in neither ruled list, but F2 conflicts with its absolute "never". The same choice qualifies §A7's clause "treating an observed later fill as correlated to an unknown request" (§A12.3). Confirm both, or keep rule 6 and §A7 absolute. Keeping them absolute would leave F2 only the terminal class, and F5's correlated transfer stays deferred.

A merely ordered send does not preserve rule 10's one-unknown-per-symbol property.

Restoring evidence does not resume trading (halt/resume §3). Its item 3 (resume) is deferred. **Not carried:** alert-channel loss with no incident, which is not a §2 trigger, and the late-effect watch. Both go to D-MON / T13 (§A12.4, §A12.5). *(Corrected 2026-10-01: the first draft quoted "a gap is an incident and halts the session", which is item 5's feed-repair bullet.
