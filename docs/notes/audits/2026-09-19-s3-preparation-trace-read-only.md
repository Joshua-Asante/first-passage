## 5. Risks and open design questions for the coordinator

Each item names the line that raises it. No code changes are proposed here.

1. **Q1 — Capture custody location for FULL_E1 N1.** `ExecutionStore.executions` is N1_ONLY-only (`CHECK(checkpoint='N1')`, `attempt_id UNIQUE`, store.py:29-36) and both stores refuse cross-capability attempts (store.py:240-241; campaign_store.py:82-83, :645-646, :1058-1059; test at test_campaign_admission.py:280). Campaign-side custody today is either a `CAPTURED` transition blob bounded by `record_byte_limit=131072` (campaign_store.py:884-885; profile.py:130) or `full_campaign_objects` rows (no size CHECK; `retain_supervision_event` bounds its own inserts :311-312). The whole N1_ONLY sign/verify/commit chain (`signing.sign_captured` :13-18, `store.get_captured_payload` :329-334, `commit_assessment` :486-541) reads `executions`. S3 has to choose (new versioned campaign tables ⇒ `user_version` 8 + layout validation, or lifting the collision rule ⇒ breaking an accepted invariant) before any interface can be written. The plan's own words: "Store/schema changes remain additive with exact layout validation" (:101) and "Snapshots and transport have one owner" (:90).
2. **Q2 — G5 launch topology.** No S2 role can run `bootstrap.py g5` with socket + credential + scratch access (§4b; `probe_container_body` :819-838 has no mounts and `NetworkMode none`; guardian `TasksMax=1` :146). "G5 runs as the metered installed qg5 role" (plan :164) is a new launch shape (host unit with `User=g5_uid`, or container with mounts), and the polkit rule, `campaign_host.cleanup` (:112-159, which knows only guardian units and `fpqs2-*` containers) and `container_ownership.campaign_scopes` (:59-70, one guardian unit + one payload slice per work) would all see a new unit kind. This also decides whether G5's charged CPU is observed via `payload/cpu.stat` (:503-504) or a different cgroup.
3. **Q3 — Worker output capture under the S2 container body.** N1_ONLY captures stdout via `docker start --attach` (launcher.py:130-155) and requires the framed result on stdout (worker.py:70; `archive_capture` decodes the frame). The S2 body sets `AttachStdout=False`, `LogConfig none` and starts through the HTTP API (:829, :837, :860). A FULL_E1 N1 worker needs an attach/stream path or an output mount, and the guardian (13 s CPU bound, 200 ms poll :867-872) would have to stream up to `output_byte_limit` (10 MB test profile) — or the service does the capture. Unresolved in the plan.
4. **Q4 — Canonical evidence is release-v1-bound.** `build_n1_evidence` rejects non-v1/N1_ONLY releases (evidence.py:200-203) and expects exactly one ATTESTED N1 execution in a `qualification_journal_snapshot/v1` (:267-272). The S3 "closed FULL_E1 checkpoint result/attestation/assessment schema" therefore forces a versioned owner change in `qualification/evidence.py` and `journal_snapshot.py` at the same time, with `compare_n1_evidence` (:428-441) and the `attempt_journal` role (`parse_proposed_artifact` :34-35) following.
