# §4 — MISLEADING (not agent-facing)

**What this section is.** Every confirmed **MISLEADING** finding from both audit rounds whose consumer is a *reader* — an operator, an author, a future triage — rather than an agent executing an instruction mid-task. MISLEADING is the tier where a stale claim **can** cause a wrong deployment, a wrong clearance, a wrong gate reading, or (in one case, M15) a real-money action. That is the whole content of the label; the COSMETIC tier is defined by the negation of it.

**Size.** **54 findings** — 43 from round 1 (`M1`–`M43`, ported from §5.2–§5.5 of the round-1 artifact) and 11 from round 2 — presented as **50 rows across 42 primary target files**, plus the mirror/index files named inside individual actions. Rows are fewer than findings because **four findings merge into three rows** where they share a file and one action discharges them: `README.md` (M6 · RDB-04 · RDB-06), the class-S haircut `RESULTS.md` (LAB-1 · LAB-2), and `core/mc/preflight.py` (M41 · M42). One round-1 row is recorded **MOOT** rather than dropped (**M13**, fixed at `ae5ffe7`).

**Where the rows are.** §4.1 root docs (9) · §4.2 rail-build + monitoring (8, one MOOT) · §4.3 instrument ledgers (5) · §4.4 ADRs + the lifecycle owner (6) · §4.5 specs / briefs / pre-registrations / closures (13) · §4.6 research bodies (4) · §4.7 constants + envelope + pre-flight (3) · §4.8 two agent-read files round 2 classified non-agent-facing (2). Then **Handoffs**, which names every shared-commit dependency — read it before opening any file.

**Evidential standing.** Every row carries its provenance in the `#` cell: **(R1)** rows were raised against a 21.4% refutation rate, **(R2)** rows against 9.7%. Round-2 findings therefore carry **slightly lower evidential standing**; the README states the two available readings of that gap and does not pretend to resolve them. The hedge is stated once, there, and is **not** repeated per row. Where a round-2 row rests on a mechanical check, the check is named in the Action cell so it can be re-run rather than trusted.

**Not here.** BLOCKERs (§2 — all three FIXED), the agent-facing MISLEADING register (its own section file — round 2's 71 agent-facing findings, including `M44` from the round-1 late-placement block, which is agent-facing by its own text), and COSMETIC. Index: [`README.md`](README.md).

**Verdict key (unchanged from round 1).** `DELETE` = retire with a tombstone or supersession record, never silent byte removal · `SIMPLIFY` = compress a restatement into a pointer or a shorter durable form · `KEEP-CORRECTED` = load-bearing and minimal, states a dead premise, needs a factual correction · `KEEP-AS-IS` = no edit owed, recorded as deliberate restraint.

**Status of these findings.** Every row is a **RECOMMENDATION pending operator ruling**. Nothing here has been applied. The four items that *are* settled (B1/B2/B3 FIXED, FU-1 RULED) appear only where they change a row's action — and they change six of them: **M13** (moot), **M18** (its "do not open the manual route" clause must now record the 08-05 override), **M15** and **M36** (both need the FU-1 ruling's narrow scope stated), **M8** (its de-scope-ADR header edge already landed), and **M42** (FU-1's one manual token trade is **not** the modelled execution-layer mitigation, and the comment must not let a reader collapse them).

### Standing constraints on every action below

* Dated bodies — session logs, closure notes, RESULTS bodies, frozen ADR §2 text, pre-registrations — are **correct history and are never edited in place** (Trap #12). Corrections land as addenda, amendment logs, or reader-intercept banners. Rows that target such a file say so explicitly.
* `DELETE` never means byte removal. It means retire with a tombstone, a `Withdrawn-by` / `Superseded-in-part-by` edge, or a struck row with the bytes still visible.
* **Nothing in this section authorizes** an edit to locked strategy parameters, Pine, `dd_protection` constants, `core/lifecycle.py` tier multipliers, allocations, `LEG_MAP`, or frozen ADR §2 decision text. §4.7's rows touching `core/` are **comments and docstrings only** — no encoded value changes anywhere, and a `firm_rules.py` value change needs an ADR plus the engine pre-flight. The **one** executable change this section proposes is to a gate script (`scripts/check_skill_refs.py`, **S-22**), which is not a governed surface — and it is specified with its expected fallout.
* The de-scope moved **deployment state**, not lifecycle: both legs remain `AUTHORIZED · MECHANISM @ 1.00×`. Any correction that lets a reader infer a demotion is a wrong correction.
