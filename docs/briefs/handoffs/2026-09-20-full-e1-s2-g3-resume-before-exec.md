## 1. Root cause (coordinator, from the run artifact — do not re-derive, do verify)

Run 35494972519, attempt `linux-3f9e8e2c…`, work `descendants`: container shim connected 06:45:52.789; the guardian retained PROCESS pid 3609 uid 65532 at 52.852 (+63 ms) and sent the first SIGUSR1 (RESUMED) at 52.860 (+71 ms); the container scope deactivated at 53.18 (+390 ms); observation 53.277 `cpu_ns=115237000`, `termination_known=true`, `oom_events=0`; no CAPTURED/COMPLETED (so the exit code was non-zero); no burner children ever appeared; the guardian exited 0; the test's own restart recovered the work to IN_DOUBT with charge 20.115 s < the 120 s reservation the test correctly requires on the overrun path. Excluded by evidence: pids limit (64), OOM (kernel log has none at that time), the guardian's overrun/OOM kill (no IN_DOUBT transition by the guardian), the probe's 30 s resume timeout (died in 0.4 s), the pre-arm dropped signal (the kernel drops, never kills, a SIG_DFL signal to a namespace init — `sig_task_ignored`/`SIGNAL_UNKILLABLE`). In the green run 35493582848 every payload was first observed 88–122 ms after shim connect; in the failed run 59–77 ms (faster host) — the descendants send simply landed earlier than the others.

**Mechanism:** `_run_probe` sends the resume as soon as `seen_pids` contains the container's init pid, and `_process_identity` verifies only start_ticks/uid/cgroup. runc's init process (`runc:[2:INIT]`, a Go program) drops to the container uid (`setupUser`) *before* `execve` of the entrypoint, so for a few tens of ms the init pid passes the UID check while still being runc. The Go runtime installs a handler for SIGUSR1 whose default action is termination (`_SigNotify+_SigKill`): a SIGUSR1 in that window kills runc init (Go `dieFromSignal` → `exit(2)` since a self-raised SIG_DFL cannot kill a namespace init) — the container exits non-zero within milliseconds, Python never runs, the guardian settles a measured charge, and the campaign is lost. The "blocked signal can never be lost" invariant only holds *after* `block_resume_signal()` runs; before `execve` the resume is lethal. Fail-closed (no credit), but a liveness defect at roughly one in a dozen payload starts on a fast host, and one that would kill real S3 workers.

**Second defect (evidence):** on the non-zero-exit-with-identity path nothing retains the container's exit code (`exit_code` is retained only inside a CAPTURED capture or a PROCESS_UNOBSERVED event), and PROCESS events carry no `comm`/`exe`, so this failure was indistinguishable from a payload crash after the fact.

## 2. Repair (frozen)

1. **Gate the resume on the exec'd entrypoint.** Extend `_process_identity` to also read `/proc/<pid>/comm` and `os.readlink('/proc/<pid>/exe')` (both readable by the guardian's uid for its own-uid processes; report if not and fall back to `comm` alone). Send SIGUSR1 only when the observed init pid's `exe` basename is the installed interpreter (`python…`) — never while `comm` is `runc:[…]`. Keep polling at the existing cadence until then; the bounded re-send window starts at the first eligible send. Retain `comm` and `exe` in every PROCESS event and in the RESUMED event (`parse_supervision_event` whitelist update; bounded strings). Keep the identity gate (`seen_pids`) semantics unchanged otherwise.
2. **Retain the payload exit on every settlement path.** Add a `PAYLOAD_EXIT` supervision event kind `{container_id, exit_code, oom_killed, finished_at}` from docker's inspect `State` (`ExitCode`, `OOMKilled`, `FinishedAt`), retained after the loop breaks and before settlement, on both the credited and the non-credited paths (PROCESS_UNOBSERVED keeps its own event too). Update the parser and, if `campaign_store.integrity()` enumerates kinds, its walk.
3. **Windows regressions** (simulated docker/proc, existing test style): (a) first observed pid reports `comm='runc:[2:INIT]'`, `exe='/usr/bin/runc'` → no SIGUSR1 sent, no RESUMED; next poll reports `comm='python3'`, `exe='/opt/ops/bin/python3.13'` → exactly one RESUMED, then the existing completion path; (b) non-zero exit with identity → `PAYLOAD_EXIT` retained with the exit code, settled measured, no completion; (c) parser rejects an unbounded/unknown-field PROCESS/RESUMED/PAYLOAD_EXIT.
4. **Linux assertions** in the existing registered cases (no new node): in `identity_retained`/`admit`, every retained PROCESS for a payload carries `exe` ending in the interpreter basename; the two-descendants case asserts a `PAYLOAD_EXIT` event exists after settlement.
