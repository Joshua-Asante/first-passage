## 0.5. Operator decisions — RULED 2026-09-21 (recommended option on each; the text below is now the frozen design constraint)

**D1 — Capture custody for FULL_E1 N1 (prep Q1, Q4).** `ExecutionStore.executions` is N1_ONLY by CHECK constraint and both stores refuse cross-capability attempts (an accepted, tested invariant); campaign-side custody today is a 131 KB-bounded transition blob or untyped object rows. Options: (a) new versioned campaign tables for capture/attestation/assessment → DB `user_version` 8 + layout validation + snapshot/v6; (b) lift the collision rule → breaks an accepted invariant (not recommended). The canonical evidence owners (`qualification/evidence.py::build_n1_evidence` rejects non-v1 releases; `journal_snapshot.parse_assessment_snapshot` is v1-only) must be versioned in the same change. **Recommendation:** (a), with the closed FULL_E1 checkpoint result/attestation/assessment schema as one versioned family (`…/v3` of the N1 chain), pinned-vector tests extended not replaced.

**D2 — G5 launch topology (prep Q2).** No S2 role can run `bootstrap.py g5` with socket + credential + scratch access: the probe container has no mounts and no network, the guardian is `TasksMax=1` / 13 s CPU. "G5 runs as the metered installed qg5 role" needs a new unit kind — a host transient unit `User=g5_uid` under the campaign's work slice (charged via its own cgroup, cleanup/ownership taught the new kind, polkit prefix unchanged) is the smallest shape. **Recommendation:** host unit under the work slice, launched by the guardian through the existing `campaign_control` prefix, with the G5 phase's reservation (`N1_G5`) as its ceiling; no container.

**D3 — Worker output and the readiness handshake (prep Q3, Q5, Q7).** The S2 container body discards stdout; the N1_ONLY path captures via `docker start --attach`. The real `worker` entrypoint has no resume handshake and would be killed by the guardian's SIGUSR1 (S2 finding, run 35543486564) or settled unobserved. **Recommendation:** the worker entrypoint calls the same `block_resume_signal()` / `/proc/self/comm` token / `await_resume()` sequence as the probe (shared helper, changes the signed runtime closure and worker image — record the new identities); output leaves the container through a bounded output mount owned by the work (a tmpfs bind under the payload slice) rather than the guardian streaming stdout; `BudgetGuard.from_contract` is replaced by a phase-limited guard supplied with the remaining N1 limits, and `parse_worker_result`/`verify_execution` compare against those same limits.

**D4 — Release/profile revision (prep Q6, §3).** Every campaign release literal pins `dispatch_enabled=False` and the profile fixed set pins `supported_checkpoints=[]`; opening N1 dispatch touches ≥12 strict consumers and the budget-profile-v3 ↔ snapshot-v5 coupling. **Recommendation:** one new release literal (`qualification_execution_release/v5`) + profile/v5 with `supported_checkpoints=['N1']`, `dispatch_enabled=True` for N1 only, `production_execution=False`; v4 and older keep refusing dispatch; fresh attempts only.
