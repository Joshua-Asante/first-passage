## A. Frameworks scan (for inspiration)

Four external traditions were scanned for how to decompose research findings into reusable atomic units. **Evidence-synthesis methodology** (PRISMA + GRADE, from systematic-review practice) treats one extracted finding per study/outcome as the atomic unit, always kept attached to its source citation *and* a separate, explicitly-graded confidence field -- the fact and the trust-in-the-fact are two distinct columns, never merged into a single true/false flag ([PRISMA 2020 checklist](https://www.prisma-statement.org/prisma-2020-checklist); [Cochrane Handbook Ch.14 -- GRADE / Summary of Findings tables](https://training.cochrane.org/handbook/current/chapter-14)). **Zettelkasten** (Luhmann's slip-box method) supplies the identity layer: one note = one self-contained, out-of-context-readable claim, given a permanent stable address so later notes can cite it by reference instead of restating it -- a discipline git repos already give for free via file paths and history ([zettelkasten.de -- The Principle of Atomicity](https://zettelkasten.de/posts/principle-of-atomicity-difference-between-principle-and-implementation/)). **Quant-finance practice** contributes two adjacent patterns: the "factor zoo" tradition (WorldQuant's [101 Formulaic Alphas](https://arxiv.org/pdf/1601.00991) / Feng, Giglio & Xiu's ["Taming the Factor Zoo"](https://www.nber.org/papers/w25481)) stores each signal as a small, independently re-derivable unit *plus* a standing redundancy-check against the accumulated set before a new one is banked; feature-store practice ([Uber Michelangelo Palette](https://www.zenml.io/mlops-database/uber-michelangelo-michelangelo-palette-feature-engineering-platform-for-consistent-offline-training-and-low-latency-onli)) enforces define-once-reference-many so a fact is computed once and pulled by reference everywhere downstream. **Knowledge-graph/ontology extraction** and **[FActScore](https://arxiv.org/abs/2305.14251)** contribute a fixed-schema constraint (facts land in a small closed set of categories, not free text) and a re-runnable verification loop (an atomic fact should be periodically re-checked against its cited source, not judged once and forgotten).

My own recommendation for this repo: this profile should lean hardest on **Zettelkasten + PRISMA/GRADE together**, because the repo already half-implements both without naming them. Zettelkasten's identity layer is just this repo's existing `file:line` citation convention -- every fact below is addressed by a stable, git-tracked location, so nothing here needs restating elsewhere; future briefs can cite this profile's facts by their original `file:line`, not by paraphrase. PRISMA/GRADE's certainty layer is *already the repo's own status vocabulary* -- `RESOLVED / FALSIFIED / AMBIGUOUS-HOLD / VOID-COVERAGE / DEAD(cost|N-SURV)` -- which functions exactly like a GRADE certainty grade attached to each extracted item. The one gap worth borrowing deliberately from the factor-zoo and FActScore traditions: this profile should be treated as a redundancy-check surface for the *next* MNQ Q-brief (does a new candidate collide with something already banked here) rather than a one-time synthesis exercise, and its facts should be periodically re-verified against source rather than assumed permanently current.
